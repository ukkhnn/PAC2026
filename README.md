# ContextWeld

**작업 맥락 기반 용접표기 해석 및 조건 추천 시스템**

> **현재 구현 기준: [데모 스펙 v1.5](docs/DEMO_SPEC.md) (2026-10-10).** Runpod에서 단일 시나리오의 인식·해석·재촬영·모의 파라미터 전달을 실행·기록하고, 로컬 관리자 화면에서 조회·재생한다. 근거 원문 적재·정확 조회/RAG도 구성한다. 아이디어 피칭이 목적이며, 데모의 실제 흐름·근거 설명을 우선하고 정확도 목표·독립 평가를 완료 조건으로 요구하지 않는다. 새 환경에서는 이 문서를 먼저 읽는다. 범위는 확정됐으며 전체 데모 구현은 아직 완료되지 않았다. 기존 기획과 충돌하면 데모 스펙이 우선한다.

ContextWeld는 선박 블록과 부재의 정형 마킹·수기 표기를 인식하고, 현재 작업지시·도면·용접 기준을 함께 검토해 작업과 용접조건 후보를 제안하는 프로젝트다. 판단 근거가 부족하거나 정보가 충돌하면 작업자에게 확인을 요청하고 그 결과를 기록한다. 사용자 수정은 별도로 저장하며, 명시적 재검토 요청에서 선택한 기록만 참조한다. 자동 학습·이력 자동 재사용은 이번 범위가 아니다.

[PAC 2026](https://ainnov.co.kr/pac2026) 분과 02 기업 문제 해결형 IR 피칭 대회의 HD현대로보틱스 미션 03을 대상으로 한다. 참가팀은 **Static Duo**다.

> 현재 단계: [공개 사진 10장의 실제 OCR/VLM·원문 4개 74청크 검색](docs/RUNPOD_INFERENCE.md)에 이어, 저장된 실제 관측을 [모사 작업지시·도면→WPS 조건 범위→HTTP 모의 수신](docs/DOCUMENT_DEMO.md)으로 연결했다. 정상 사례는 수신 응답을 기록했고, 필수값 누락·문서 공정 충돌·개정 불일치·실제 판독 불일치는 전송을 보류했다. 이어서 [사용자 수정 저장 → 명시적 재검토 → 선택적 모의 전달](docs/EXPLICIT_REVIEW.md)을 서버 CLI로 구현해 실제 저장 묶음에서 재검토만 성공(`succeeded`·`not_requested`), 별도 전달 요청으로 `received`, 수정 뒤에도 문제가 남아 `blocked`, 수신기 미가동 결함 주입 시 `failed`를 확인했다. 원본 입력 1,173개 파일 해시는 그대로이며 문서 범위 규칙 재검토의 새 모델 호출은 0회다. Runpod 테스트 83개와 로컬 재검증 83개가 통과했다. 기준일: 2026-10-10.

> 장면 구성: 기존 [정형 마킹·작업대 기준 장면](docs/ISAAC_SCENE.md)을 보존하고, [조선소 수직 3면 강판·중앙 수기 메모 장면](docs/ISAAC_SHIPYARD_SCENE.md)의 `live-03`을 구성했다. UR10 손목 카메라의 실제 관절 이동·A/B RGB와 고정 작업등의 금속반사, Foxglove 손목/전체 장면 영상 수신을 검증했다. A에서는 반사가 합성 식별자의 일부를 가리고 B에서는 같은 표기와 `J01`·화살표가 육안으로 보인다. 이 장면의 OCR/VLM 판독과 문서 연결은 아직 수행하지 않았다.

> 최신 인식 실험: [CTX-001 고정 이미지 맥락 비교](experiments/context_ablation/REPORT.md)를 실제 Runpod 모델로 완료했다. 공개 사진 9장·주어진 표기 위치 28개에서 OCR 완전 일치 2개, 이미지·후보 목록의 올바른 선택 16개, 합성 작업 문서 추가 시 14개였다. 정답이 없는 목록에서는 3/4개를 잘못 확정했다. 후보 기반 복구 사례와 문서 추가의 악화를 함께 기록했으며, 실제 현장 정확도나 Isaac 장면 성능을 뜻하지 않는다. 과거 서버 이전 파일럿 성적은 현재 발표 근거에서 제외한다.

WPS 검수는 선택한 헤더·대표층 1의 전사 확인이며 사람의 적용 승인이 아니다. 사진의 실제 재질·두께·현장 WPS 적용성은 미확인이고, 합성 장면의 `J01`과 문서의 `JOINT-DEMO-01`도 아직 연결하지 않았다. 팔의 A/B 이동은 `pre_captured`로 기록하는 예약 시연이며 모델 판단으로 움직이는 폐루프가 아니다. [문서 검토 한 건의 오프라인 HTML 조회](docs/DOCUMENT_REVIEW_VIEWER.md)는 구현해 정상 `received`·누락/관측 충돌 `blocked`의 실제 묶음 3개를 내보냈다. 원본 582개 파일 해시 보존·신규 테스트 6개와 HTML 구조·표시 내용 검사를 통과했으며, 브라우저 파일 URL 제한으로 시각 검수는 미완료다. 명시적 재검토는 문서 범위 규칙 재검토이며 시각 관계의 모델 재해석과 수정 입력 화면은 구현하지 않았다. P1 장면·RGB 생성은 달성했지만 전체 P2·P3·P4와 여러 실행 통합·A/B 관리자 재생은 미완료다. 별도 [실험실](experiments/README.md)의 과거 비교 결과와 현재 부분 실행을 구분한다.

실제 조선소 저장 A/B의 마킹에서 작업지시·공통명세·현대/두산 입력·HTTP 수신까지 연결한 최신 실행은 [통합 파이프라인](docs/WELD_PIPELINE.md)을 따른다. B의 `BISB30N-15`·`J01`·지시 대상을 판독해 대상과 제조사 명령을 함께 전달했고 양쪽 `received`를 확인했다. 위의 이전 부분 구현 설명 중 조선소 인식·문서·전달 미연결 상태는 이 실행으로 갱신됐다. 실제 팔 이동·실기 용접·좌표 경로 생성은 별도다.

## 첫 장면 실행

Python 3.10 이상에서 별도 설치 없이 저장소 루트에서 실행한다. 사진을 읽는 명령이 아니라 직접 작성한 후보와 가상 작업지시를 연결하는 예제다.

```sh
PYTHONPATH=src python3 -m contextweld data/examples/part-order-scene.json --case normal
```

`--case ambiguous`, `--case stale`, `--case wrong-context`로 확인 필요·만료·다른 블록 사례를 볼 수 있다.

## 해결하려는 문제

선박 부재의 표기는 문자·숫자·기호·약어가 혼재하며 오염·반사·훼손으로 판독이 어렵다. 문자 인식 결과만으로는 해당 표기가 어떤 부재, 작업 위치, 방향, 용접 작업을 의미하는지 판단하기 어렵다.

ContextWeld는 시각 정보에 작업 맥락과 기준 문서의 근거를 연결한다. 맥락이 해석에 도움이 되는 경우뿐 아니라 잘못된 맥락이 오판을 유발하는 경우도 검증한다.

## 주요 기능 목표

- 정형 마킹과 수기 표기의 영역 검출 및 인식 후보 표시.
- 부재·위치·방향·용접 지시의 구조화.
- 현재 작업지시·도면·WPS의 대상·개정·유효 시점과 일관성 검토.
- 표기 규칙과 용접 기준 검색을 통한 근거 및 조건 후보 제시.
- 불확실하거나 충돌하는 결과의 작업자 승인·수정·보류.
- 원본 이미지부터 해석·추천·확인 이력까지의 추적성 확보와 명시적 요청에 의한 별도 재검토.

```text
사진 → 표기 검출·인식 → 의미 구조화 → 맥락·기준 대조
                                     ↓
                            조건 후보 또는 확인 요청
                                     ↓
                              작업자 확인·이력 저장
```

```text
.
├── README.md
├── .gitignore
├── docs/
│   ├── PROJECT_BRIEF.md
│   ├── MILESTONES.md
│   ├── DATA_REQUIREMENTS.md
│   ├── SOURCES.md
│   └── references/           # 기획서와 미션 원문
├── src/contextweld/          # 애플리케이션 구현
├── tests/                    # 핵심 기능 검증
├── experiments/              # 기술 선택 실험·실제 출력·레포트
├── scripts/                  # 데이터 준비·실행·평가 보조 도구
├── configs/                  # 비밀정보를 제외한 설정
├── data/
│   ├── README.md
│   ├── raw/                 # 원본 현장 자료, Git 제외
│   ├── examples/            # 공개 가능한 개발·시연 사례
│   ├── knowledge/           # 공개 가능한 표기 규칙·기준 자료
│   └── eval/                # 공개 가능한 평가 사례·정답
└── output/
    ├── evaluations/         # 평가 결과
    ├── demo/                # 시연 영상·스크린샷
    └── presentation/        # 발표자료
```

현재 `src/contextweld`에는 후보 연결, 실제 OCR/VLM 실행·기록, 문서 추출·검색, 문서 조건 검사와 모의 수신, 수정 저장(`corrections.py`)·명시적 재검토(`review.py`) 모듈이 있다. `scripts`에서 인식·검색·문서 연결·묶음 검증과 Isaac 장면 생성·ROS 영상 송출을 실행한다. `configs/document_demo`에는 모사 작업지시·도면·범위 검토용 프로파일이 있고, `configs/isaac_scene`에는 기존 작업대와 새 조선소 수기 장면의 설정을 각각 보존한다. `data/knowledge`에는 원문 위치와 검수 범위를 보존한 WPS 구조화 자료가 있다. `tests`에는 자동 테스트, `data/examples`에는 기존 가상 작업지시 예제가 있다. A/B 촬영과 인식·문서 처리를 한 실행으로 연결하는 작업, 시각 관계 재해석·수정 입력 화면·관리자 화면은 후속 범위다. experiments/의 OCR은 별도 실험용이다. 원본 현장 자료와 생성 산출물은 기본적으로 Git 추적에서 제외한다. 데이터 공개 기준은 [데이터 안내](data/README.md)를 따른다.
