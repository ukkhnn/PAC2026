# 데이터 관리

Runpod에서 데모 자료를 받는 시작점은 [자료 준비 안내](../docs/setup/RUNPOD_DATA_SETUP.md)다. `scripts/prepare/prepare_demo_data.py`가 `configs/demo_data_sources.json`의 고정 Steel OCR 사진과 근거 원문을 `data/raw/demo-bootstrap-v1/`에 준비하고 실제 파일 해시를 기록한다. 서버 실행 결과와 확보 상태는 안내 문서에 남긴다.

`examples/part-order-scene.json`에 직접 작성한 부재번호 후보와 가상 작업지시·개정 이력이 있다. `synthetic` / `synthetic_manual`로 구분하며 사진 OCR 결과나 현장 데이터가 아니다. 독립 평가셋은 아직 없다. 입력 규약은 [첫 장면 안내](../docs/runs/FIRST_SCENE.md)를 따른다. 기획서와 미션 원문은 [docs/references](../docs/references)에 있다.

## 배치

| 폴더 | 용도 | Git 관리 |
|---|---|---|
| raw | 제공받은 원본 사진·현장 자료 | 기본 제외 |
| examples | 개발·시연 사례 | 공개 가능한 자료만 포함 |
| knowledge | 표기 사전·용접 기준·작업 맥락 자료 | 공개 가능한 자료만 포함 |
| eval | 개발 자료와 분리한 평가 사례·정답·버전 | 공개 가능한 자료만 포함 |

원본을 직접 수정하지 않고 가공본을 분리한다. 공개할 수 없는 기준 문서·평가 자료도 `raw/` 또는 저장소 밖에서 관리하고, 공개 문서에는 자료의 구조와 준비 방법만 기술한다.

## 기록 항목

출처, 수집·제공일, 사용 가능 범위, 실제·합성·시연용 구분, 정답 근거와 검토 상태를 남긴다. 구체적인 파일 형식과 스키마는 M0에서 정한다.

## 평가 분리

같은 사진의 회전·밝기 변형본을 개발과 평가에 나누어 넣지 않는다. 작업 이력에 평가 대상의 정답이 미리 포함되지 않도록 한다. 평가 기준을 변경하면 버전과 이유를 기록하고 이전 결과와 구분한다.

평가 결과는 `output/evaluations/`에 저장한다. 생성 산출물은 기본적으로 Git 추적에서 제외하며, 공개할 결과표·그림은 검토 후 `docs/`에 선별해 포함한다.
