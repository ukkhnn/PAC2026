# 용접 인식 파이프라인 문서 적용 계획

작성일: **2026-10-10** · 버전: **1.3** · 상태: **실제 관측·모사 문서·WPS 범위 검토·모의 전달 연결, 현장 적용 미확정**

**TWI는 기호 해석에, LANL WTS는 작업지시 구조에, 기입된 WPS는 조건 추출에, 선급·안전자료는 적용조건 검토에, 제조사 설명서는 마지막 출력 변환에 사용한다.** 각 자료에서 필요한 항목을 먼저 구조화하고, 실행 중에는 현재 대상과 연결된 문서만 읽는다.

이 계획은 사용자가 확정한 `mermaid-diagram (1).png`의 각 단계에 어떤 문서를 넣고 무엇을 추출할지 정한다. **원문 확보·구조 추출·검수·적재, 현재 작업의 정확 조회, 작업 범위로 제한한 RAG를 이번 구현 범위로 둔다.** 아래 설계 목표와 마지막 절의 실제 구현 범위를 구분한다. WPS는 용접절차서, WTS는 작업별 용접기법서다.

이 문서는 자료를 적용할 설계 기준이다. 원문이나 검수된 지식을 대신하지 않는다. 현재 `data/knowledge`에는 LANL WPS의 선택 헤더·적용정보·대표층 1을 원문과 전사 대조한 [구조화 자료](../data/knowledge/lanl-wps-3501-reviewed.json)가 있다. 이는 에이전트의 전사 검수이며 사람의 도메인 검토나 현장 적용 승인이 아니다. [기존 문서 실험](../experiments/REPORT-2026-10-09.md)의 영어 요약 140단어·개발 질문 9개 결과와 이번 원문 연결을 구분한다.

2026-10-10 Runpod에 D1 TWI, D2 WTS, D3 WPS와 D9 계열 현대 `arccond` 원문을 내려받고 실제 해시를 기록했다. [자료 준비 안내](RUNPOD_DATA_SETUP.md)를 따른다. 원문 4개에서 74청크를 추출한 [위치 검색](RUNPOD_INFERENCE.md)에 이어, 실제 저장 관측을 모사 작업지시·도면과 연결하고 WPS Rev.1의 대표층 1 범위를 HTTP 모의 수신기로 전달했다. 누락·공정 충돌·개정 불일치·판독 불일치 보류도 확인했다. 나머지 층과 단위 미확정 항목, 사진·현장 적용 검토는 남아 있다. [문서 연결 실행 안내](DOCUMENT_DEMO.md).

**아이디어 피칭에 필요한 작은 원문 묶음을 실제로 연결하는 것이 우선이다.** 독립 평가셋이나 검색 정확도 합격선은 필수가 아니다. 시나리오에서 사용한 값·단위·표 행의 근거를 확인하고, 소량 사례로 누락·충돌 동작과 오류를 살펴본다. 원문 표 검수와 출처 보존은 유지하며 성능 비교는 필요할 때 후속으로 진행한다.

## 기준 흐름과 기존 데모의 관계

첨부 그림의 전체 흐름은 원본 사진 → 문자·숫자 인식 및 화살표·기호·접합부 검출 → 표기와 대상의 관계 해석 → 공통 용접 작업 명세 → 조건·누락·충돌 검증 → 제조사별 변환 → 로봇 작업 프로그램 또는 등록 작업 선택이다. 작업지시·도면·WPS는 관계 해석과 공통 명세에 들어가고, CAD·3D 센서·좌표 보정 결과는 제조사 변환에 들어간다.

흐리거나 가려진 관측은 재촬영으로, 대상·의미의 모호함과 필수정보 누락·지시 충돌은 작업자 확인으로 보낸다. 확인·수정된 정보는 별도 저장하고, 작업자의 명시적 요청으로 새 실행에서 관계 해석부터 다시 검토한다. 사진의 판독과 문서의 해석을 구분하여 기록한다.

| 구분 | 이 계획에서 다루는 범위 | 기존 문서와의 관계 |
|---|---|---|
| 전체 구조 | 첨부 그림의 모든 노드와 두 피드백 경로 | 이번 문서의 문서 배치 기준 |
| 현재 데모 | A/B 재촬영, 문서 적재·정확 조회·범위를 제한한 RAG, 조건 검사, 모의 수신, 오프라인 기록 조회 | [데모 구현 기준](DEMO_SPEC.md) v1.4의 실행·기록 계약 사용. 실제 한 시나리오 연결과 소량 기능 확인 우선 |
| 수정 후 재검토 | 수정 근거를 별도로 저장하고 명시적으로 새 검토를 시작 | 데모 §6.2와 동일. 새 `run_id`로 검토하며 자동 학습·이전 수정 자동 검색·자동 재전송은 제외 |
| CAD와 제조사 변환 | 실제 연동에 필요한 문서·보정자료와 변환 기준까지 정의 | 기존 데모는 실제 경로·보정·장비 전송을 제외하므로 모의 프로파일과 구분 |

실행·수정·내보내기 범위는 `DEMO_SPEC.md`, 인식 계약은 [OCR 구성](OCR_PIPELINE_SPEC.md), 원문 적재와 조회는 이 문서, 장비 입력명·단위·조건은 [용접로봇 입력 상세 명세](WELDING_ROBOT_INPUT_SPEC.md)를 기준으로 맞춘다. 실제 장비 실행까지 범위를 확대할 때는 데모 스펙을 별도로 갱신한다. 현재는 모의 전달까지다.

`symbol_rules.json`에 기업 수기 약어를 임의로 추가하지 않는다. 도면의 표준·표기 체계를 먼저 정하고, 해설의 특정 체계를 모든 용접기호에 일반화하지 않는다. 현장 표기사전이 생기면 적용 회사·작업 범위와 버전을 별도로 둔다.

WTS의 빈칸에서 실제 작업값을 추출할 수는 없다. 모사 작업지시는 문서 등록 정보에 `document_origin=synthetic_demo`를 기록한다. 이는 OCR 계약의 결과 필드 `source_kind`와 다른 층위다. 실제 문서 내용을 가져온 필드는 `document`, 문서 근거 없이 데모용으로 가정한 값은 `fixture`로 구분하고, 전자는 문서의 모사 여부도 함께 보여준다. 실제 작업지시를 확보하면 같은 필드에 원문 근거를 연결해 교체한다. D3의 역사적 공개 절차는 추출 예제이며 현재 조선소의 승인 절차로 승격하지 않는다.

## 초기 문서 묶음 구성

**현재 부분 실행은 직접 작성한 작업지시·도면과 D3의 선택 구조화 필드를 연결한다.** D1·D2·D3·D9 원문 검색은 유지한다. 아래 표는 A/B 전체 시나리오까지 필요한 자료이며 모두 구현된 것은 아니다. D3를 실제 장면의 적용 WPS로 확정하려면 장면의 공정·재질·두께·자세를 별도로 검토해야 한다. 맞지 않으면 적용불가로 남기고 적합한 다른 WPS를 선정한다.

| 준비물 | 구체적으로 만들 내용 | 구분 |
|---|---|---|
| 지원 표기 목록 | 부재/이음 표기, 한정된 용접기호, 화살표의 의미와 적용 표준 | 사람이 검토한 설계 입력 |
| 모사 도면 | 부재·이음 ID, 재질·두께·형상·치수, 용접기호, 도면 개정 | 직접 작성한 `drawing.json`과 검토용 도면. 공개 그림을 실제 장면 도면으로 둔갑시키지 않음 |
| 모사 작업지시 | 작업·부재·이음·도면·WPS 참조, 개정·상태·유효시점 | 현재 `configs/document_demo/work_orders.json`, 실제 현장 지시와 구분 |
| WPS 구조화 파일 | 원문 헤더·적용범위와 패스별 행을 분리해 저장 | 공개 원문에서 추출한 값과 검토 상태 |
| 문서 목록 | 각 문서의 ID·판본·해시·적용범위·로컬 경로·이용조건 | `documents.json` |
| 모의 출력 프로파일 | 필요한 대상·문서·조건 항목과 단위, 범위값 허용 여부 | `target_profile.json`, `purpose=demo_mock` |
| 시나리오 기대 결과 | A/B의 문자·관계·문서 근거·최종 판정 | 추론 입력 밖의 확인 자료. 정상 작업지시·도면과 구분 |

D4는 기록 구조에 반영하고 D8은 작업자 확인 항목으로 연결한다. D5는 재료 후보 설명이 필요할 때, D6은 선택 공정의 규칙 검증이 필요할 때 추가한다. D7은 원문 확보·검수 후 D8과 중복을 확인해 보완한다. 자료 수를 늘리기 위해 전체 문서를 한꺼번에 검색 대상으로 넣지 않는다.

첫 모의 수신 계약으로 **범위값을 전달하는 문서 검토용 프로파일**을 구현했다. D3가 제공하는 범위를 보존하며 단일 전류·전압을 선택하지 않는다. 범위의 모든 조합이 물리적으로 적합하다는 뜻도 아니다. 단일 설정값이 필요한 시연을 선택한다면 별도의 모사 레시피와 선정 근거를 추가한다. 어느 방식이든 실제 용접 실행 명령은 아니다.

[공개 자료·시나리오 조사](PIPELINE_OPEN_RESOURCES_AND_SCENARIO.md)의 PCC 교육자료는 문서 추출·충돌 검증용 별도 사례로 유지한다. PCC, LANL, KOBELCO의 항목을 섞어 하나의 승인 WPS를 만들지 않는다.

## 문서 준비와 실행 중 조회

### 실행 전에 처리할 일

1. **원문 등록:** PDF/HTML을 확보하고 `document_id`, 개정, 원문 해시, 확보일, 출처 URL, 적용범위, 이용조건을 기록한다. 파일 확보일과 문서 발행·개정일은 다른 필드다.
2. **구조 추출:** 텍스트 PDF는 본문·표 구조를 먼저 추출하고, 스캔 페이지는 문서 OCR을 적용한다. 그림과 표는 페이지·영역을 유지한다.
3. **필드 검토:** 특히 숫자·단위·병합 셀·표 머리글·패스 행을 원문과 대조한다. 빈칸, `0`, `N/A`, 앞 행과 동일함을 서로 다른 상태로 보존한다.
4. **관계 등록:** 작업지시가 어느 도면·WPS 개정을 참조하는지 연결한다. 명시적 참조와 내용 유사성에 의한 후보 연결을 구분한다.
5. **규칙 작성:** 문서의 조건을 구조화하고 출처 조항을 붙인다. 자동 추출 규칙은 사람이 검토하기 전 적용 판정에 사용하지 않는다.
6. **묶음 고정:** 시나리오에 사용할 문서 개정·해시와 지원 항목을 고정한다. 실행 A/B 중 문서가 바뀌면 동일 조건 비교로 취급하지 않는다.

### 실행할 때 처리할 일

| 조회 순서 | 조회 조건 | 반환할 내용 |
|---|---|---|
| 작업 선택 | 프로젝트·블록·작업 시점과 관측 부재 후보 | 유효 작업지시 후보. 최신 취소·보류 지시에서 과거 지시로 복귀하지 않음 |
| 대상 연결 | 작업지시의 도면 ID·개정, 관측 화살표·기호·이음 | 관련 도면 영역·객체와 관계 후보 |
| WPS 선택 | 작업지시/도면의 WPS 참조, 재질·두께·공정·자세 | 해당 WPS 개정의 적용정보와 필요한 패스 행 |
| 보조 근거 | 적용 표준·공정·작업환경에 맞는 문서 유형 | 필요한 기호 설명·규칙 조항·안전 확인항목 |
| 명세 구성 | 위 결과의 필드 ID와 참조 관계 | 조건 후보·누락·충돌을 포함한 공통 명세 |

### 정확 조회와 RAG의 역할

**현재 작업을 고르는 일과, 그 작업에 필요한 설명을 검색하는 일을 분리한다.** 작업지시가 WPS의 특정 개정을 가리키면 그 참조를 먼저 해석한다. 검색 점수가 높은 다른 WPS로 대신하지 않는다.

| 정보 | 조회 방식 | 근거 보존 |
|---|---|---|
| 프로젝트·부재·이음·작업지시·상태·효력·개정 | 구조화된 정확 ID 조회와 유효성 검사 | 선택·제외한 ID와 이유, 참조 개정 |
| 기호 의미·기술 설명·관련 조항 | 작업 범위·문서 유형·표준·개정으로 제한한 RAG | 검색 질의·필터·반환 근거 ID·원문 위치 |
| WPS 적용범위·패스별 숫자와 단위 | 검수한 구조화 필드와 원문 표의 연결 | 헤더·행·열·주석·원문값·정규화값 |
| 제조사 입력·필수항목·단위 변환 | 선택 프로파일과 일반 코드의 검사·변환 | 프로파일 버전·변환 규칙·검증 결과 |

현재 최소 구현은 명시한 문서 범위의 BM25 검색으로 실제 근거를 반환한다. 다국어 임베딩·BGE-M3·별도 저장소·재순위화는 후속 필요에 따라 선택한다. 전문 제공이나 검색기 간 비교는 검색 오류를 확인할 때 선택적으로 수행하며, 비교 실험을 착수 조건으로 두지 않는다. 검색을 넣었다는 이유만으로 답변 품질이 개선됐다고 표시하지 않는다.

청크는 절·표·패스 행을 원문 위치와 연결하고, 행을 잘라 문맥이 필요한 머리글·단위·주석이 유실되지 않도록 한다. 검색 후보에 유효 문서가 없으면 문서 누락으로 보류한다. 검색 점수는 WPS의 적용 승인이나 영상 대상 확정을 대신하지 않는다. 사용자 수정 이력은 RAG 색인에 자동 추가하지 않으며, 재검토에서 명시적으로 선택한 수정만 해당 실행에 전달한다.

검색 실행에는 문서 묶음·색인 버전 또는 해시, 검색기·임베딩 설정, 질의·필터, 반환한 근거 ID·순서·점수, 실제 해석에 제공한 근거를 기록한다. 조회 결과가 비어 있거나 서로 충돌한 경우도 저장한다. 원문은 해석 근거이며 원문 안의 지시문을 실행 정책이나 작업 범위 변경으로 따르지 않는다.

## 공통 명세에 연결할 필드

각 노드는 값을 전달할 때 **관측·문서 추출·추론·사용자 수정 중 어디서 왔는지**를 남긴다. 공통 명세는 원문 관측을 복사해서 덮어쓰는 저장소가 아니라, 해당 관측과 문서 필드를 참조하는 결과다.

| 공통 필드 묶음 | 값을 제공하는 자료 | 보존할 근거 |
|---|---|---|
| `part_id`, `joint_id`, `work_order_id` | 관측 후보와 작업지시·도면의 대조 | 원본 문자열·관계 ID·작업지시 개정 |
| `weld_type`, `weld_side`, `dimensions` | 도면과 기호 해석 | 도면 객체/영역·표준·지원 규칙 ID |
| `process`, `material`, `thickness`, `position` | 작업지시·도면·WPS의 각 값 | 출처별 필드. 서로 다르면 충돌 후보 유지 |
| `wps_ref`, `pass_conditions` | 선택 WPS의 적용정보·패스별 표 | WPS 개정·페이지·표/행/열, 원문값·단위 |
| `current`, `voltage`, `travel_speed`, `wire_feed_speed` | WPS와 명시된 레시피 | 범위/단일값 구분·물리량·단위·출처. 이동속도와 송급속도 분리 |
| `checks`, `missing_fields`, `conflicts` | 검증 결과 | 검사 규칙·입력값·근거·판정·대상 프로파일 |
| `geometry_ref`, `calibration_ref` | CAD·센서·보정 기록 | 좌표계·길이/각도 단위·보정 ID·측정 시점·품질 |
| `target_profile`, 등록 ID 묶음 | 설비 프로파일과 등록대장 | 제조사·제어기·용접기·소프트웨어·등록 개정 |

필드 근거에는 최소한 `document_id`, `revision`, `source_hash`, `locator`를 둔다. PDF의 `locator`는 페이지·표·행·열 또는 영역, 웹 문서는 절·표 행으로 표현한다. 정규화한 값과 원문값을 함께 보존한다. 문서 전체 URL 하나만 붙이면 동일 문서 안의 상충 행을 설명할 수 없다.

예를 들어 전류 범위는 WPS의 특정 패스 행에서 가져오고, 그 행의 적용 두께는 같은 WPS의 적용정보와 함께 검사한다. 전류 범위의 가운데 값을 자동 선택하거나 다른 행의 전압을 조합하지 않는다. 패스 행이 대표 예시라는 주석도 함께 전달한다. [D3]

## 조건 검증과 두 피드백 경로

| 검사 | 사용할 문서·관측 | 불일치 또는 누락 시 처리 |
|---|---|---|
| 표기 판독 가능성 | 현재 원본 프레임·인식 출력·품질 관측 | 관측 개선 가능성이 있으면 재촬영. 새로운 프레임으로 실제 재인식 |
| 대상·의미 확정 | 화살표 끝점·접합부 후보·도면 관계·기호 규칙 | 후보가 둘 이상이면 작업자 확인. 화살표 방향을 용접 진행 방향으로 확정하지 않음 |
| 문서 유효성 | 작업지시 상태·유효시점·도면/WPS 참조 개정 | 누락·취소·개정 불일치는 확인 요청. 유사한 문서로 대체하지 않음 |
| WPS 적용범위 | 공정·작업방식·모재·두께·자세·소모재 | 적용불가 또는 미확인 기록. 교육/반자동 절차의 자동화 적용을 추정하지 않음 |
| 수치와 조합 | 패스별 조건·단위·열입력 등 명시된 제약 | 범위 이탈·단위 불명·조합 부적합은 보류. 범위만 있고 설정값이 필요하면 누락 |
| 문서 간 충돌 | 작업지시·도면·WPS의 같은 필드 | 양쪽 값과 근거 표시. 일반 해설로 구체 지시를 덮어쓰거나 임의 교집합을 확정하지 않음 |
| 선급 요구 | 대상에 적용되는 검수된 D6 조항 | 적용 조항·판본이 미확정이면 미검증. 다른 법역/프로젝트의 기준을 자동 적용하지 않음 |
| 안전 확인 | D7/D8의 해당 항목과 현재 현장 확인 기록 | 문서에 규칙이 있다는 사실만으로 현장 상태를 통과시키지 않음. 모사 상태도 출처 표시 |
| 장비와 좌표 | D9/D10, 셀 프로파일, CAD·보정·등록대장 | 실제 프로그램 생성에 필요하면 누락으로 보류. 모의 프로파일 결과와 분리 |

안전 체크는 해당 조건의 관측값이 없으면 `unknown`이다. 적용 대상이 아니라면 이유를 붙여 `not_applicable`로 남긴다. 현재 데모에서 실제 장비 안전 검증을 수행하지 않는다는 사실을 일반적인 안전 통과로 표현하지 않는다. 모의 수신 프로파일에서 요구하지 않는 실물 좌표의 부재는 기록하되, 모의 수신 자체와 실제 실행 준비도를 혼합하지 않는다.

### 재촬영 문서 적용

재촬영에는 WPS 수치가 아니라 **어떤 필수 표기를 확정하지 못했는지**가 필요하다. 작업지시는 필수 대상·필드의 범위를 제공하고, 사진과 인식 결과는 재촬영 사유를 제공한다. 현재 A/B 데모에서는 고정된 B 자세를 사용할 수 있다. 문서가 누락된 상황은 다른 각도 촬영으로 해결되지 않으므로 작업자 확인으로 보낸다.

### 작업자 수정 후 재검토 문서 적용

1. 원본 이미지의 해당 영역, 연결 후보, 충돌하는 문서 필드와 개정을 함께 보여준다.
2. `correction_id`, 원래 결과 ID, 수정 전후 값, 작성 주체·시각·사유를 별도 저장한다. 문서 변경이라면 새 문서 개정과 효력도 남긴다.
3. 명시적으로 재검토를 시작하면 새 `run_id`를 만들고 `parent_run_id`, `review_request_id`, 선택한 `correction_ids`를 기록한다. 원본 관측·선택 문서 스냅샷·수정 기록을 새 입력으로 연결한다. 사람의 수정값은 모델이 읽은 값으로 표시하지 않는다.
4. 관계 해석 → 공통 명세 → 검증을 다시 수행하고 새 결과 ID를 만든다. 사용자 확인 한 번으로 모든 조건·좌표·장비 검사를 통과시키지 않는다.
5. 원래 결과·명령·수신 응답은 그대로 둔다. 재검토 뒤 모의 전달은 별도 명시적 동작이며 새 명세·명령 ID를 쓴다. 재검토는 자동 학습이나 자동 재전송을 뜻하지 않는다. 로컬 기록 재생 중에는 재검토도 실행하지 않는다.
6. 완료된 실행 묶음은 수정하지 않는다. 이후 수정은 묶음 밖 추가 기록, 재검토는 사용한 원본 관측·문서·수정 스냅샷을 포함한 별도 묶음으로 내보낸다. 원래 ID와 해시를 보존하고 새 촬영·OCR 결과로 표시하지 않는다.

명시적 재검토는 현재 데모의 구현 범위다. 저장과 조회만 구현한 중간 상태를 전체 완료로 표시하지 않는다. 재검토 입력 위치는 데모 스펙 O07에서 선택하고, 로컬 읽기 전용 재생 기능과 분리한다.

## 제조사 변환에 적용할 문서

**제조사 설명서는 필드의 의미와 형식을 정의하고, WPS는 공정의 적용조건을 제공한다.** 둘을 대조한 뒤 선택한 셀의 등록정보를 사용한다. 일반 설명서만으로 실제 등록된 조건번호를 알 수는 없다.

| 필요한 정보 | 제공할 문서 | 처리 |
|---|---|---|
| 전류/송급/파워 중 지령 종류 | D9의 연결 용접기별 설명 + 셀 프로파일 | A, m/min, %를 서로 대체하지 않음 |
| 절대전압/전압 보정/아크길이 보정 | D9 + 실제 용접기 모드 | WPS의 V를 보정값 필드에 직접 넣지 않음 |
| 시작·종료·위빙·속도 필드 | 선택 버전의 명령/설정 설명 + 등록 조건 | 단위·정의·필수항목 대조. 제조사 기본값을 승인된 공정값으로 사용하지 않음 |
| 로봇 프로그램·제어기 조건·용접기 Job | 셀의 등록대장 | 서로 다른 ID로 관리하고 프로그램/조건의 버전 연결 |
| 경로·토치 자세·보정 | 실제 CAD·교시/센서·TCP 및 좌표 보정자료 | 사진의 픽셀 좌표로 대체하지 않음. 등록 작업도 대상 셀·지그와의 일치 필요 |

실제 제조사 프로파일이 없으면 공통 명세와 모의 파라미터만 만든다. 실제 프로그램 생성과 등록 작업 선택은 별도 경로로 두되, 어느 쪽도 공개 WPS만으로 실행 준비가 끝났다고 판단하지 않는다. 세부 필드·단위·장비별 조건은 [용접로봇 입력 상세 명세](WELDING_ROBOT_INPUT_SPEC.md)를 우선 적용하고 해당 설치 버전에서 확인한다. D9는 현대를 선택했을 때의 원문 예시다. 두산을 선택하면 상세 명세의 해당 공식 원문·버전을 등록하며 현대 필드와 혼합하지 않는다.

## 기록과 구현 순서

원문과 문서 스냅샷·근거는 [데모 구현 기준](DEMO_SPEC.md) §7의 `evidence/`에, 구조화 추출·검색·해석 결과는 `results/`에, 전달값과 ACK는 `commands/`에 연결한다. 기본 폴더 구조를 유지하며 문서 검토 부분 실행은 `document-demo-bundle.v1`로 구분한다. 각 실행의 `manifest.json`에는 실제 사용한 문서 개정·해시·모사 여부와 조회 설정을 연결한다. 현재 계약의 `spec_version`은 `demo-1.4+ocr-1.2+documents-1.3`, 재사용한 인식 결과 형식은 `recognition.v1`이다. 이전 인식 묶음의 버전과 내용을 바꾸지 않는다.

`run_kind`·`delivery_requested`와 요청 범위별 성공 판정은 데모 스펙 7.2절을 따른다. 전달 미요청 재검토는 문서·관계·조건 검증 완료로 성공 종료할 수 있다. 이미 내보낸 결과를 뒤늦게 전달하려면 새 재검토·전달 실행을 만들며 완료된 묶음을 변경하지 않는다.

오프라인 화면에는 필드값·단위·문서명·개정·페이지/절·요약을 함께 제공한다. 이용조건이 허용하는 경우 원문 페이지도 포함한다. 원문을 포함하지 못하면 외부 링크와 요약을 구분해 표시하며 오프라인 원문 열람이 가능하다고 주장하지 않는다.

| 순서 | 만들 산출물 | 완료 조건 |
|---|---|---|
| 1 | 지원 표기·모사 도면·작업지시·원문과 문서 목록 | 작업→도면→WPS 참조와 실제/모사 출처가 명확함. 원문 확보·이용조건·해시 기록. 평가 정답은 별도 |
| 2 | D1 규칙과 D3 구조화 필드 | 지원 기호, WPS 숫자·단위·행·주석이 검수됐고 원문 근거까지 추적됨 |
| 3 | 현재 작업 정확 조회와 범위를 제한한 RAG | 다른 부재·취소 지시·다른 개정이 섞이지 않음. 검색 근거와 최종 답을 분리해 검증 |
| 4 | 관계 해석과 공통 명세 | 사진의 표기→이음 후보와 문서 필드가 연결되고 미확정 값이 보존됨 |
| 5 | 검증과 피드백 분기 | 판독 문제는 재촬영, 의미·문서 문제는 확인으로 분기. 누락·충돌이 정상값으로 바뀌지 않음 |
| 6 | 모의 변환과 기록 | 프로파일 필수값만 근거와 함께 전달. 범위/단일값 구분, `execution_authorized=false`, ACK 기록 |
| 7 | 오프라인 문서 근거 조회 | 서버 없이 이미지→관계→문서 근거→전달값을 따라갈 수 있음 |
| 8 | 명시적 수정 재검토 | 새 실행·선택 수정·근거 스냅샷을 검사. 원본 유지·자동 학습/검색/재전송 없음 |

실제 CAD·보정·장비 자료 연동은 현재 데모 완료 조건에 넣지 않는다. 모의 프로파일이 요구하지 않는 실제 좌표 누락을 정상 모의 전달의 실패로 처리하지 않으며, 실제 실행 준비 상태는 미확인으로 유지한다.

### 피칭 데모에서 확인할 문서 동작

**선택한 한 시나리오의 실제 문서·검색·출력 연결을 먼저 확인한다.** 기대 값과 근거 위치는 확인 자료로 두고 추론 프롬프트에 정답표를 넣지 않는다. 필요한 경우 누락·충돌을 포함한 소량 입력을 추가해 동작과 오류를 기록한다. 별도 독립 자료집·정량 합격선은 데모 완료 조건이 아니다.

| 확인 항목 | 남길 증거 |
|---|---|
| 정확 조회 | 시나리오의 작업·부재·WPS·개정이 연결되고, 다른 대상·무효 지시를 채택하지 않는지 확인 |
| RAG | 실제 질의·필터·반환 근거와 해석에 사용한 부분. 없는 근거를 생성해 채우지 않음 |
| 필드 추출 | 사용한 WPS 패스 행·단위·범위·머리글·주석을 원문과 대조 |
| 관계와 명세 | 필요한 필드와 근거 연결, 소량 누락·충돌 입력에서 보류되는지 확인 |
| 관리자 조회 | 화면의 값·문서명·개정·페이지·행이 저장된 근거와 일치 |

원문 검수·실제 검색 기록·오류 표시는 유지한다. 근거 회수율·모델 비교·독립 평가가 필요해지면 후속 실증으로 계획한다. 정량 성능을 제시한다면 표본 수와 맞힌 수를 함께 쓰고, 같은 자료의 파생본을 독립 사례로 부풀리지 않는다. 미확인 안전항목은 `unknown`, 실기 좌표는 이번 모의 프로파일의 적용 범위와 구분한다.

## 2026-10-10 최소 구현의 경계

초기 검색은 명시한 문서 ID 범위의 BM25를 사용한다. HTML/Markdown의 절·원문 줄과 PDF의 페이지·단어 영역을 보존한다. 기존 74청크 색인의 미등록 개정 `null`은 유지한다. 새 WPS 구조화 자료에는 원문 헤더를 대조한 Rev.1과 근거를 기록한다. 정확 조회는 이 구조화 자료의 ID·개정·원문 SHA-256을 검사하고, 검색 청크는 같은 원문 해시의 보조 문맥으로 연결한다. 검색 색인의 개정을 몰래 바꾸거나 없는 개정의 대체 근거로 사용하지 않는다. 기존 검색 실행은 [Runpod 인식·검색 안내](RUNPOD_INFERENCE.md), 후속 조건 연결은 [문서 연결 실행 안내](DOCUMENT_DEMO.md)를 따른다.

### 실제 관측에서 문서 범위 전달까지

저장된 `steel-batch-20261010-02`의 `frame-007`에서 OCR/VLM 문자 관측은 모두 `BISb30N-15`였다. 원문을 보존하고 대문자로 정규화한 `BISB30N-15`를 기존 작업지시 연결 로직에 넣었다. 작업지시·도면은 그 문자열을 식별자로 삼아 직접 작성한 `synthetic_demo` 자료다. 이 연결은 사진의 실제 부재·이음·공정·재질을 확인하거나 현장 매칭 정확도를 측정한 결과가 아니다. 사진 원본과 기존 모델 출력은 보존했고 새 모델 호출 없이 별도 문서 실행을 저장했다.

| 원문 검토 범위 | 반영한 내용과 한계 |
|---|---|
| 헤더·대표층 1 | Rev.1, 선택 적용정보와 2쪽 대표층 1의 표 머리글·행·열·영역·원문 해시를 기록. 에이전트가 텍스트와 렌더를 대조했고 `human_reviewed=false`·`process_approval=false` |
| 전달 범위 | 전류 130~250 A, 전압 24~28 V, 이동속도 7~18 in/min. 원문 범위와 단위를 보존하며 단일 설정값을 선택하지 않음 |
| 주석·제약 | 대표층 예시, 열입력 상한, GWS/WFP·프로젝트 승인 필요, 반자동 기법, 외부 현장·로봇 적용 미확정 등을 함께 전달 |
| 미확정 | 사진의 실제 재질·두께·이음, 선택 필드의 불명확한 치수 단위, 범위 조합의 물리적 적합성. 원문 2~4층은 구조화 범위 밖 |

서버의 다섯 실행과 로컬·Runpod 테스트 각 59개를 확인했다.

| 실행 | 결과 |
|---|---|
| 정상 문서 검토 | 실제 관측→모사 작업·도면→WPS 범위 필드·근거 검사→서버 내부 HTTP 모의 수신. `succeeded`, ACK `received` |
| 필수 전압 누락 | `needs_review`, 전달 `blocked`, 명령 없음 |
| 모사 도면의 공정 충돌 | `needs_review`, 전달 `blocked`, 양쪽 근거 보존 |
| 없는 WPS 개정 참조 | `needs_review`, 전달 `blocked`, 다른 개정으로 대체하지 않음 |
| 실제 판독 불일치 | `frame-005`의 OCR/VLM 문자열 차이를 보존, `needs_review`, 전달 `blocked` |

성공 범위는 `run_kind=document_demo`, `capture_mode=public_dataset`, `evaluation_scope=document_review`의 조건 검토와 모의 전달뿐이다. `application_authorized=false`, `execution_authorized=false`, `demo_complete=false`를 유지한다. 실제 WPS 적용 승인, 표기→실제 이음의 시각 관계 검증, A/B 재촬영, 수정·명시적 재검토와 관리자 화면은 미완료다.

새 묶음은 기존 인식 묶음 사본·모사 문서·전사 근거·검색 발췌·검증·HTTP 명령과 응답을 보존한다. 전체 원문 PDF는 포함하지 않으며 미포함을 표시한다. 저장·해시 검증 성공을 오프라인 원문 조회나 관리자 재생 완료로 해석하지 않는다.
