# ContextWeld 마일스톤

기준일: **2026-10-17** (개발 반영 2026-10-16). 현재 범위는 [데모 스펙 v1.7](DEMO_SPEC.md), [OCR 구성 v1.2](../spec/OCR_PIPELINE_SPEC.md), [문서 적용 계획 v1.3](DOCUMENT_APPLICATION_PLAN.md)을 따른다. 아래 현재 범위별 완료 기준과 **논의용 작업 분할안**을 구분한다. 새 일정·소요 시간·세부 분할은 아직 확정하지 않았다.

단일 반사·재촬영 시나리오를 Runpod에서 실행·저장하고 로컬 관리자 화면에서 재생한다. **아이디어 피칭을 위한 전체 흐름과 설명 가능한 근거가 우선이다.** 인식·관계·문서 처리는 데모 입력으로 동작을 확인하고, 높은 정확도·독립 평가·엄밀한 모델 비교는 완료 조건으로 요구하지 않는다. 10월 2일에 작성한 과거 날짜별 로드맵은 현재 실행 계획에서 제거했다. 과거 계획은 Git 이력에 남으며 대회 일정의 원문은 [참고 자료](../sources/SOURCES.md)에서 확인한다.

## 1. 실제 준비 상태

[서버 복구 로컬 준비](../audit/INSTRUCTIONS/server-artifact-recovery-local-prep.md)는 보존 사본 5건 해시 일치와 회수 계획까지이며 서버 실물 복구는 미완료다. 10월 16일 로컬 회귀 161개 통과 기록이 있으며 실제 GPU 재촬영·대시보드 어댑터·요청에 따른 새 RGB는 아직 확인하지 않았다.


2026-10-10 통합 실행: [마킹 → 제조사 입력 → 수신 연결](../runs/WELD_PIPELINE.md)을 실제 조선소 저장 A/B RGB로 실행했다. A 판독의 등록 부재 조회 실패 후 B의 `BISB30N-15`·`J01`·지시 대상을 읽고 시연 작업지시/도면·공개 WPS·등록조건으로 연결했다. 대상과 현대/두산 명령을 함께 전송하여 양쪽 HTTP200 `received`와 원문 일치를 확인했다. 로컬 관리자에 실제 기록을 추가했고 신규8/기존 모의전달7 테스트가 통과했다. 저장 프레임 선택이며 실제 팔 이동·아크 실행·좌표 경로 생성은 별도 범위다. 아래 이전 상태 표보다 이 완료 기록이 우선한다.

2026-10-10 확인 당시 서버 송출 장면은 `output/isaac-shipyard-20261010/live-03/`이며 기존 `output/isaac-scene-20261010/live-01/`은 보존한다. 로컬로 내려받은 사본은 `output/context-ablation-20261010/isaac-live-03/`에 있고, [데이터·모델 출처](../sources/DATA_MODEL_PROVENANCE.md)는 이 로컬 경로를 기록한다. 같은 실행의 서버 경로와 로컬 사본 경로이며 다른 실행이 아니다.

두 장면은 `capture_mode=pre_captured`, `recognition_feedback_enabled=false`인 예약 A/B 시연이다. 새 장면의 표기 `BISB30N-15`·`J01`·화살표는 합성 텍스처다. 부재 문자열은 실제 라벨 `B1Sb30N-15`의 오독·정규화 파생값이며 실제 라벨 정답과 구분한다. `J01`과 문서의 `JOINT-DEMO-01`은 시연 도면의 `joint_marking_map`으로 연결했고, 실제 이음을 확인한 연결은 아니다. 고정 증거는 최초 정착 `frames/`에 있고 반복 시연의 `stream/`만 계속 갱신된다. P1·P3는 달성했고 전체 P2·P4는 미완료다.

[문서 검토 한 건의 오프라인 HTML 조회](../runs/DOCUMENT_REVIEW_VIEWER.md)는 부분 구현을 마쳤다. 실제 정상·누락·관측 충돌 묶음 3개 내보내기, 원본 582개 파일 해시 보존, 신규 테스트 6개와 HTML 구조·표시 내용 검사를 통과했고 명시적 재검토 묶음 조회도 지원한다. 브라우저 파일 URL 제한으로 시각 검수는 미완료다. 환경의 일부 확인이나 문서 작성만으로 다른 구현 단계를 완료로 표시하지 않는다.

## 2. 현재 범위별 완료 기준

[데모 스펙](DEMO_SPEC.md) 12절의 P0~P5를 추적한다. 이 표는 작업을 반드시 직렬로 실행하라는 의미가 아니다.

|---|---|---|
| P0 장면·입출력 | 마킹/대상 정답, 등록된 원문·조건표, 문서 적용범위, 모의 필드 | 부분 구현: 문서 검토용 모사 작업·등록조건·범위 필드와 두 장면 고정, 장면 표기와 작업문서를 시연 도면의 `joint_marking_map`으로 연결. 실제 적용조건과 실측 형상·재질은 미확인 |
| P1 RGB 생성 | 동일 장면에서 시점만 달리한 A/B RGB와 촬영 설정 | 달성: 기존 작업대 live-01과 조선소 수기 live-03의 UR10 손목 A/B·고정 반사·원본 RGB·Foxglove 수신 확인. 기존 설정·출력 보존 |

## 3. 마일스톤 분할 제안 — 논의 전 초안

`[추론]` 기존 P2에 인식·문서·검증·전달이 몰려 있어 실패 원인을 구분하기 어렵다. 인식과 문서 기반을 나누고, 시뮬레이터와 병렬로 검증하는 아래 분할을 제안한다. M 번호는 **아직 채택되지 않은 작업안**이며 위 P 번호를 대체하지 않는다.

| 제안 | 할 일 | 완료를 판단할 증거 | 대응 범위 |
|---|---|---|---|
| M0 입력·근거 준비 | 지원 표기·대상·최종 필드를 정하고 원문 등록·표 검수·데모 기대값 준비 | 사진의 표기가 어떤 문서·표 행·출력 필드로 이어질지 추적 가능 | P0 |
| M1 인식·관계 연결 | PP-OCRv6 medium+Qwen3-VL-8B로 데모 표기·기호/대상 관계를 실제 추론 | 실제 입력·출력과 필요한 필드 확인. 오류가 진행을 막을 때만 구성 보완 | P2 일부 |
| M2 문서·조건 연결 | 작업·개정 정확 조회, 범위 제한 RAG, WPS 조건·단위 검사 | 올바른 근거 문단/표 행 조회, 잘못된 대상·개정·적용조건의 배제 | P2 일부 |

### 의존성과 병렬 진행

- M0의 최소 표기·필드·데모 기대값부터 정한다. 원문 적재와 검수가 모두 끝나기 전에도 독립적인 OCR·RGB 실행 가능성을 먼저 확인할 수 있다.
- M1·M2·M3는 병렬 진행한다. M1은 기존 Steel OCR 사진으로 먼저 연결할 수 있고 M2의 문서 연결도 시뮬레이션 완성을 기다리지 않는다.
- M4는 실제 A/B와 인식·문서 결과를 받아 통합한다. M5는 미리 합의한 실행 묶음 예제로 골격을 만들 수 있지만, 완료 판정은 M4의 실제 기록으로 한다.
- M6는 M4의 요청·촬영 계약 위에 연결하므로 관리자 화면 완성을 기다릴 필요는 없다. M5와 병렬로 진행할 수 있다.
- 시연에 필요한 입력·기대 흐름은 M0에서 정한다. M7은 실제 실행과 녹화 내용의 일치를 확인하며, 뒤늦게 독립 성능 평가를 필수로 추가하지 않는다.
