# ContextWeld 프로젝트 개요

ContextWeld는 PAC 2026 분과 02의 HD현대로보틱스 미션 03을 위한 용접표기 해석 및 조건 추천 프로젝트다. 이 문서는 문제 정의와 현재 구현·평가 범위를 설명한다. 기준일은 2026-10-10이다. 확정 범위와 완료 조건은 [데모 스펙](DEMO_SPEC.md)을 따른다. 제출 기획서의 장기 구상과 현재 구현 범위는 구분한다.

## 미션

미션 03은 선박 블록과 부재에 표시된 정형 마킹과 비정형 수기 문자·숫자·기호·약어를 인식하고, 의미와 작업지시를 해석해 용접 작업과 조건에 연결하는 것을 요구한다.

대회 분과는 기업 문제 해결형 IR 피칭이다. 프로토타입과 함께 문제 적합성, 판단 근거, 검증 결과, 후속 실증 계획을 제시하는 것을 목표로 한다. 공식 요구사항은 [미션 정의서](references/mission-03.pdf), 제출 아이디어는 [기획서](references/idea-proposal.pdf)를 참조한다.

## 제안 방식

시각 인식으로 문자·기호·관계 후보를 생성하고, 현재 프로젝트·부재·이음·작업지시·개정을 정확하게 연결한다. RAG는 그 범위에 적용되는 표기 규칙과 용접 문서의 근거를 검색한다. 검수한 WPS 표의 값과 적용조건은 구조화해 검사하고, 관측·문서·해석을 구분해 기록한다.

촬영 품질 때문에 필수 정보를 읽을 수 없으면 재촬영을 요청한다. 의미·대상 연결이 불명확하거나 기준이 충돌하면 확인 또는 보류한다. 작업자 수정은 원본과 별도로 저장하고, 명시적 요청에 한해 별도 실행으로 재검토한다. 다른 작업의 수정 이력 자동 참조, 자동 학습, 자동 명령 재전송은 이번 범위에서 제외한다.

[추론] 검증할 가설은 작업 맥락이 표기 의미 해석에 도움이 된다는 것이다. 별도 [개발 표본 실험](../experiments/REPORT-2026-10-09.md)은 있으나, 최종 인식·해석 스택과 현장 성능은 미검증이다. 잘못되거나 오래된 맥락이 오판을 강화하는 경우도 평가한다.

## 기능 범위

| 미션 요구 | 프로토타입 목표 |
|---|---|
| 표기 검출 | 복수 영역 표시, 문자와 비문자 혼동 사례 확인 |
| 정형·수기 인식 | 인식 후보와 불확실성 표시, 회전·저조도·부분 훼손 사례 평가 |
| 의미·작업지시 해석 | 부재·위치·방향·작업 종류 구조화, 표기 간 관계와 규칙 근거 연결 |
| 작업·조건 판단 | 입력 기준에 따른 후보, 작업 위치·방향·순서 표현, 누락·충돌 시 확인 요청 |
| 시각화 | 서버에서 저장한 원본 영역·해석·근거·재촬영·전달 기록을 로컬 관리자 화면에서 조회·재생 |
| 추적과 연계 | 이미지부터 수정 이력·모의 수신 응답까지 연결된 실행 묶음 내보내기 |

시뮬레이션은 반사로 판독이 어려운 자세 A와 각도를 바꾼 자세 B의 한 장면으로 구성한다. Runpod에서 시뮬레이터·인식·해석·모의 파라미터 전달을 실행하고, 기록을 내려받아 로컬에서 읽기 전용으로 조회·재생한다. 사전 촬영한 시뮬레이터 RGB 방식과 실제 재촬영 요청에 따른 팔 이동 방식은 구현 수준을 구분한다. 손목 카메라를 장착한 로봇팔은 촬영에만 사용한다.

이번 결과물은 아이디어 피칭용이다. 한 시나리오에서 실제 모델의 관측 → 재촬영 → 문서 근거 → 모의 전달 흐름을 설명 가능하게 연결하는 것을 우선한다. 실제 원문을 갖춘 작은 문서 묶음과 소량 입력의 기능 확인·오류 기록을 준비한다. 정교한 OCR 비교, 독립 평가셋, 정량 정확도 합격선은 데모 완료의 필수 조건이 아니라 후속 선택이다. 구체 마킹·필수 출력 필드·초기 모델·검색 구성은 해당 세부 명세에서 관리한다. 실제 용접, 실기 제어·CAD/3D 좌표 보정, 모델 학습, 공장 시스템 실시간 연동은 제외한다.

## 판단 원칙

- 이미지에서 읽은 내용, 맥락으로 추정한 내용, 기준 문서의 근거, 작업자 확인 결과를 구분한다.
- 용접조건은 적용 가능한 기준에 연결한다. 근거가 없으면 수치를 생성해 확정하지 않는다.
- 모델 점수를 검증된 정답 확률로 표현하지 않는다.
- 작업지시의 개정·유효 시점·보류·취소 상태를 정확 조회하며, 예정 상태를 실행 완료로 간주하지 않는다.
- 수정은 별도 기록으로 보존한다. 명시적 재검토는 새 실행으로 남기고 원본 결과·과거 전달을 덮어쓰지 않는다.
- 시연용 자료·규칙·모의 출력을 실제 현장 자료·모델 출력과 구분한다.
- 화면상의 작업 위치 표현과 로봇 좌표·경로 생성은 별도 기능으로 취급한다.

## 도메인 개념

| 개념 | 필요한 구분 |
|---|---|
| 부재와 표기 | 식별번호·위치·방향·용접 지시 |
| 용접 종류와 치수 | 필릿 용접의 각장·목두께 등 서로 다른 항목 |
| WPS | 용접절차시방서. 재질·두께·용접법·자세 등 적용 조건과 용접 변수의 근거 |
| 표준 기호와 현장 약어 | 표준 도면 지식과 현장 수기 약어의 의미 |
| 작업계획과 수정 기록 | 현재 지시의 유효 상태·개정과 사용자의 수정 기록을 분리 |

WPS와 기호 설명의 근거는 [참고 자료](SOURCES.md)에 정리한다. 실제 적용할 기준과 현장 표기 사전은 확보 후 검증한다.

## 시연 사례

| 사례 | 확인할 동작 |
|---|---|
| 통합 시연 | 반사로 판독 불가 → 재촬영 요청 → 다른 자세 RGB → 실제 재인식·해석 → 모의 파라미터 전달 |
| 모호·충돌 검증 | 복수 후보·표기와 문서 충돌·근거 누락 시 확정 보류 |
| 수정·재검토 검증 | 수정만으로 결과가 바뀌지 않으며 명시적 요청은 별도 실행으로 연결 |
| 잘못된 맥락 검증 | 오래되거나 다른 작업의 문서로 임의 확정하지 않는지 확인 |

주요 영상은 한 시나리오이며, 나머지 검증 사례를 별도 시뮬레이션 장면으로 모두 만들 필요는 없다. 마킹 자체가 잘못돼 사람도 판단할 수 없는 사례의 해결은 이번 시연에서 제외한다.

## 피칭용 확인과 후속 평가

필수 확인은 시나리오 A/B의 실제 인식 출력, 재촬영 사유, 표기와 대상 연결, 참조한 문서·표 행, 최종 전달값이 기록으로 이어지는지다. 필요한 소량 입력에서 오류·보류·실행 실패를 확인하고 설명에 남긴다. 인식 정확도 최적화보다 전체 흐름과 근거의 설명 가능성을 우선한다. 모델 간 엄밀한 비교와 독립 성능 평가는 필요할 때 후속으로 진행한다.

정답은 출처와 검토 근거를 남기며, 정답표·수정 이력·시뮬레이터의 내부 정답을 실제 인식 출력처럼 사용하지 않는다. 단일 시연이나 소량 입력의 결과를 일반 정확도·현장 성능으로 주장하지 않는다. 향후 성능 비교를 주장할 때는 원본 단위 분리·표본 수·실패 유형을 갖춘 별도 평가를 설계한다. 인식 구성은 [OCR 명세](OCR_PIPELINE_SPEC.md), 자료 구축은 [문서 적용 계획](DOCUMENT_APPLICATION_PLAN.md), 전달 필드는 [제조사 입력 명세](WELDING_ROBOT_INPUT_SPEC.md)를 따른다.

## 후속 실증

사용자와 도입 주체, 기존 확인 절차에 연결할 위치, 필요한 현장 데이터, 실증의 성공 기준을 구체화한다. 시간·비용 절감 효과는 측정값과 가정을 구분한다. 현재 도입 대상과 효과 수치는 확정되지 않았다.
