이 문서는 2026-10-05의 조사와 설계 제안을 보존한 자료다. 현재 구현의 기준은 데모 스펙, OCR 명세, 문서 적용 계획, 제조사 입력 명세다. 시뮬레이션·추론·모의 전달은 서버에서 실행·기록하고, 로컬 화면은 내려받은 기록을 읽기 전용으로 재생한다.

아래의 Work Memory·후속 작업 이력 참조·학습·현장 시스템 연동은 과거 확장 제안이며 현재 구현 범위가 아니다. 현재는 사용자 수정을 별도 저장하고, 명시적 요청에 한해 새 실행으로 재검토한다. 다른 작업 이력 자동 참조·자동 학습·자동 재전송은 제외한다. 현재 목표는 아이디어 피칭이며, 한 시나리오의 실제 모델·문서 근거·모의 전달 연결과 소량 기능 확인을 우선한다. 아래의 엄밀한 비교·독립 평가·정량 성능 기준은 후속 선택이며 데모 완료 조건이 아니다. 외부 자료는 최초 조사일의 기록이며 이번에 재검증하지 않았다.

01 / THE BIG PICTURE

사진을 읽는 것과 작업을 결정하는 것은 달라

미션은 철판 위의 문자·숫자·기호·약어를 찾아내고, 부재·방향·위치·작업지시로 해석한 뒤, 입력된 기준에 맞는 용접조건이나 후보를 제시하는 일이야. 불확실한 판단은 작업자에게 확인하고 원본까지 추적할 수 있어야 해. [1]

따라서 평가 대상도 두 가지야. 글자를 얼마나 잘 읽는지와, 그 글자를 얼마나 올바른 작업 의미에 연결하는지를 따로 봐야 해.

02 / FOUNDATIONS

이음 · 용접 형태 · 공정 · 자세를 나누자

이 문서에서는 주로 철강 구조물의 용융 용접을 떠올리면 돼. 모재와 필요한 용가재를 녹여 접합부를 만들고, 식은 뒤 두 부재가 연결되는 방식이야. 모든 용접이 이 방식만 쓰는 것은 아니야. [2]

구분답하는 질문예시 / 혼동하면 생기는 일

Joint configuration		두 부재가 어떻게 만나는가?맞대기·T이음·겹치기. T자로 만난다고 용접 공정까지 정해지지는 않아.

03 / READING THE MARKS

용접 표기를 문장처럼 읽는 법

도면의 표준 용접기호와 철판 위의 현장 약어는 구분해야 해. 전자는 적용 표준·도면 범례로 읽고, 후자는 현장 표기 규칙과 작업 문서를 확인해야 해. 미션은 정형 마킹과 비정형 수기를 모두 포함해. [1]

보이는 요소기본 의미주의할 해석
화살표 / 기준선접합부 지시 / 기호를 놓는 기준기준선이 실물 용접선은 아니고, 화살표가 곧 로봇 진행 방향도 아니야.
직각삼각형 / V필릿 / V형 홈 용접 기호철판 위의 손글씨 V도 같은 뜻인지는 현장 규칙을 확인해야 해.
a / z / 숫자목두께 / 각장 / 치수판 두께와 용접 치수를 분리하고, 단위·위치까지 읽어야 해.
접점의 원 / 깃발둘레 용접 / 현장 용접원은 화살표와 기준선의 접점에 붙는 보조기호야. 물체 전체를 용접하라는 뜻으로 확대하지 않아.
기호 오른쪽 숫자길이·개수·간격 관련 지시단속 용접의 숫자 배열과 간격 정의는 적용 표준으로 읽어야 해.
꼬리공정·문서 참조 등 추가 정보항상 같은 정보를 적는 고정 필드는 아니야.

기호 개요와 치수: TWI [3] · 체계 및 정의: ISO 2553:2019 [4]. 표준 원문 전체를 대체하는 기호집은 아니야.

위·아래만 보고 뜻을 확정하지 말자. ISO 2553의 System B는 단일 기준선을 사용해 아래/위로 화살표 쪽/반대쪽을 구분하고, System A는 실선과 파선으로 구분해. 도면의 표기 체계와 단위를 먼저 확인해야 해. [4]

04 / GLOSSARY

개발하면서 다시 찾게 될 용어들

뜻과 함께 “우리 시스템에서 왜 필요한지”를 붙였어. 아래에서 한글·영문·약어로 찾을 수 있어.

부재 · 블록Member / Part · Block

부재는 구조를 구성하는 개별 요소, 블록은 여러 부재를 조립한 선체의 큰 제작 단위로 이해하면 돼.

연결점: 표기를 어느 물체에 연결할지 정하는 식별 단위. 구체적인 번호 체계는 [확인 필요].

패널 · 보강재Panel · Stiffener

판 구조와 그 강성을 보강하는 부재. 자동화 설비는 패널·소조립 등 제작 대상에 따라 구성이 달라져. [6]

연결점: 촬영 장면과 작업 단위를 먼저 좁히는 기준.

모재 · 용가재Base / Parent metal · Filler metal

모재는 붙일 원래 재료, 용가재는 접합을 위해 추가하는 재료야. [2]

연결점: 겉모양이 비슷해도 적용 가능한 절차는 다를 수 있어.

비드 · 패스Bead · Pass / Run

비드는 용착 금속의 띠, 패스는 용접을 한 번 진행하는 단위로 이해하면 돼.

연결점: 용접부 하나를 여러 번 나눠 채울 수 있어. “한 번 작업함”과 “완료”를 구분하자.

루트 · 토Root · Toe

루트는 용접의 뿌리 쪽, 토는 용접 표면과 모재 표면이 만나는 경계야. [2]

연결점: 치수와 결함 위치를 설명하는 기준.

열영향부HAZ · Heat affected zone

녹지는 않았지만 용접 열로 조직·성질이 영향을 받은 모재 영역이야. [2]

연결점: 사진 속 비드 모양만으로 전체 접합 품질을 판단할 수 없어.

용입Penetration · CJP / PJP

용접이 접합부 내부로 형성되는 정도와 관련돼. 완전용입과 부분용입 요구를 구분해. [2]

연결점: 겉으로 보이는 폭을 용입 깊이라고 읽으면 안 돼.

각장 · 목두께Leg length z · Throat thickness a

필릿 용접의 서로 다른 단면 치수. a6과 z6을 같은 값으로 저장하면 의미가 사라져. [4]

연결점: 숫자·단위·치수 종류를 함께 보관.

개선 · 루트 간격Groove preparation · Root gap

개선은 용접할 모서리를 가공하는 것, 루트 간격은 조립한 접합부 뿌리 쪽의 틈이야.

연결점: 표기에 없는 형상 조건은 도면·측정 자료로 확인해야 해.

취부 · 가용접Fit-up · Tack welding

취부는 부재의 위치·간격을 맞추는 조립 작업, 가용접은 본 용접 전 위치를 유지하는 짧은 용접이야.

연결점: 눈에 용접 자국이 있다고 본 용접 완료로 처리하면 안 돼.

용접 자세 · 진행 방향Position · Travel direction

자세는 중력에 대한 작업 배치, 진행 방향은 용접이 진행하는 방향이야.

연결점: 이미지 좌표·선체 방향·로봇 좌표를 구분해야 해. 자세 코드는 적용 표준과 함께 보관.

연속 · 단속 용접Continuous · Intermittent weld

연속은 이어서, 단속은 구간을 나누어 용접하는 지시야. [3]

연결점: 길이·구간 수·간격을 단순한 전체 길이 하나로 합치지 않아.

MIG · MAGMetal inert / active gas welding · GMAW

와이어를 공급하며 보호가스를 쓰는 아크 용접. MIG는 불활성 가스, MAG는 활성 가스 성분을 사용하는 구분이야. [9]

연결점: 용접 형태와 공정을 분리하고 가스·와이어 조건도 확인.

TIGTungsten inert gas welding · GTAW

비소모성 텅스텐 전극을 쓰는 아크 용접. 필요하면 용가재를 별도로 공급해. [10]

연결점: 공정마다 전극·용가재·설정 체계가 달라.

FCAWFlux-cored arc welding

내부에 플럭스가 든 와이어를 사용하는 아크 용접. 외부 보호가스를 쓰는 방식과 자체 보호 방식이 있어. [11]

연결점: 와이어의 종류나 보호 방식이 다른 절차를 혼용하지 않아.

SAWSubmerged arc welding · 서브머지드 아크 용접

입상 플럭스 아래에서 아크가 형성되는 용접 공정이야. 이름의 submerged는 물속 용접이라는 뜻이 아니야. [12]

연결점: 현장 공정이 무엇인지 먼저 알아야 입력과 조건 후보를 좁힐 수 있어.

예열 · 층간온도Preheat · Interpass temperature

예열은 용접 전 가열, 층간온도는 여러 패스 사이에 관리하는 온도야. [13]

연결점: 작업 조건에는 전류·전압뿐 아니라 온도와 작업 상태도 포함될 수 있어.

용접절차시방서WPS · Welding Procedure Specification

해당 작업에 사용할 용접 변수와 조건을 정한 절차 문서야. [5]

연결점: 조건 추천의 근거. 문서 ID·개정·적용 범위를 함께 확인.

절차 인정 기록PQR / WPQR

용접절차의 적합성을 뒷받침하는 시험·검증 기록. 명칭과 인정 경로는 적용 규정에 따라 달라져. [5]

연결점: WPS의 근거이지 개별 작업의 실행 로그는 아니야.

작업지시서 · 개정Work instruction / Work order · Revision

현재 수행할 대상·작업과 관련 문서의 변경 버전. 실제 문서 구성은 [확인 필요].

연결점: 최신 문서라는 이유만으로 모든 부재에 소급 적용하지 않아.

공정 순서 · 변형Sequence · Distortion

열의 누적과 수축을 고려해 작업 순서·방향을 정하기도 해. [7]

연결점: 로봇의 이동거리만 최소화해서 순서를 정하면 충분하지 않아.

전류 · 전압 · 이동속도Current · Voltage · Travel speed

용접조건을 구성하는 서로 다른 변수. 단위도 각각 A, V, 길이/시간으로 달라.

연결점: 치수 하나로 세 값을 생성하지 말고 적용 가능한 절차·설정 근거에 연결.

비파괴검사NDT · Non-destructive testing

검사 대상을 파괴하지 않고 검사하는 방법군. 육안·초음파·방사선 등 여러 기법이 있어. [8]

연결점: 표기 인식 성공은 용접 품질 검사 합격을 뜻하지 않아.

표기사전 · 적용 범위Marking dictionary · Scope

특정 약어의 뜻과 그것이 통하는 현장·공정·프로젝트 범위를 연결한 자료.

연결점: FW 같은 약어도 해당 현장 규칙과 대조해 해석하자.

CAD · BOM · MES설계 · 부품 구성 · 제조 실행 정보

CAD는 형상·도면, BOM은 부품 구성, MES는 생산 실행 관련 정보를 다루는 시스템이야.

연결점: 맥락 공급원이 될 수 있지만 현장 보유·연계 가능 여부는 [확인 필요].

추적성Traceability

추천 결과에서 원본 표기·해석·문서 근거·사람의 확인까지 거슬러 확인할 수 있는 성질.

연결점: 미션의 필수 요구. 최종 결과만 저장하면 부족해. [1]

사람의 확인HITL · Human in the loop

08 / PROPOSED CONTEXT DESIGN

맥락은 “근거를 연결하고 적용성을 검증하는 구조”

[추론] 초기의 “비전 점수와 맥락 점수를 섞자”에서 한 단계 더 나아가야 해. 잘못 연결된 문서는 높은 점수를 받아도 쓸 수 없고, 규칙 충돌은 평균 점수로 상쇄해서는 안 돼. 먼저 입력의 소속과 기준의 적용 가능성을 검증하고, 남은 후보의 순위를 정하는 편이 설득력 있어.

③ 적용 기준표기 규칙, 도면, WPS의 버전·적용 범위·승인 상태기준 미확인으로 조건 확정 제한
④ 현재 작업 상태예정·취부·가용접·본 용접·검사·보수, 상태 변경 시점계획과 사실을 나눠 표시

관계형 DB, RAG, LLM의 역할

구성맡길 일 [추론]구체적인 설계
관계형 DB정확한 식별·버전·상태·참조 관계부재 ID, 용접부 ID, 도면 개정, WPS ID, 작업 이벤트. 숫자 범위는 구조화해서 비교.
문서 검색 / RAG현장 규칙과 설명 문서의 근거 구간 찾기승인 상태·프로젝트·버전으로 먼저 범위를 제한. 문단뿐 아니라 표 제목·단위·행·각주를 함께 유지.
LLM / VLM후보 의미 구성, 문맥 관계 해석, 설명과 확인 질문원문 근거와 구조화된 출력을 요구. 모델 스스로 만든 가정을 사실 필드로 저장하지 않음.
규칙 검사기필수 항목·적용 범위·명시적 충돌 확인출처가 확인된 제약만 사용. 미확인을 참으로 처리하지 않고, 그럴듯한 점수로 충돌을 덮지 않음.

DB 전체를 임베딩할 필요는 없어. [추론] 식별자와 버전은 정확 조회, 설명·예외 문구는 검색으로 맡기자. 예를 들어 부재 ID → 도면 개정 → 용접부 → 적용 WPS 연결은 관계로 관리하고, 해당 WPS의 주의사항을 근거 문단으로 조회하는 방식이야.

RRF를 핵심 판정기로 쓰지 않는 이유

[추론] RRF 같은 순위 결합은 검색 후보를 모으는 단계에서 비교해볼 수 있어. 하지만 시각적 해석 후보와 문서 검색 순위는 같은 대상을 매긴 순위가 아닐 수 있어. 같은 해석 후보로 정렬한 뒤에도, 순위만으로 적용 불가 문서를 배제하거나 신뢰도를 확률로 해석할 수는 없어.

당시 제안은 규칙만 → 규칙+맥락 → 필요시 학습된 후보 순위화 비교였어. 학습된 후보 순위화는 현재 데모 범위에서 제외하며 최종 인식·관계·근거 검증은 현재 명세를 따라. 신뢰할 수 있는 제약에 명확히 위배되는 후보는 자동 추천에서 제외하고, 입력 자체가 불확실해 제약 만족 여부를 모르면 사람에게 보낼 후보로 남겨두는 식이야.

같은 모호한 표기, 다른 맥락

모두 설계 설명용 합성 사례야. 실제 인식 결과나 성능 수치가 아니야.

사진에서 ‘a6’ 또는 ‘a8’이 보임

부재 ID와 현장 표기 규칙이 없어서 이 표기가 표준 치수 지시인지도 확정할 수 없어.

  • 두 문자 후보와 원본 영역을 남겨.
  • 숫자 6이나 8을 용접조건으로 바로 넘기지 않아.
  • 확인 질문: “대상 부재 ID 또는 연결할 작업지시를 알려줘.”
출력: 문자·의미 후보 / 조건 미정 / 대상 연결 필요

같은 용접부의 유효 도면에 a6 지시가 있음

부재·용접부 연결과 도면 적용 범위가 확인됐고, 이미지 후보에도 a6이 있어.

  • a6을 지지하는 근거로 도면 항목을 연결해.
  • 사진에서 확실히 읽은 것과 문서가 지지한 것을 따로 보여줘.
  • WPS 적용 정보까지 충족될 때 조건 후보를 조회해. 자동 확정 허용 여부는 별도 정책과 검증으로 정해.
출력: a6 해석 우선 후보 / 도면 근거 / 남은 조건 확인

사진은 a8로 선명한데, 연결된 도면은 a6

OCR 오류, 잘못된 부재 연결, 도면 개정 누락, 승인된 현장 변경 등 여러 가능성이 있어.

  • 평균 점수를 내서 a6으로 덮어쓰지 않아.
  • 원본 a8 판독과 도면 a6 지시를 함께 표시해.
  • 확인 질문: “이 도면이 현재 부재에 적용되는 버전인지, 변경 지시가 있는지 확인해줘.”
출력: 불일치 보류 / 원인 후보 / 변경 근거 요청

추천 데이터 단위: 증거를 가진 주장

[추론] 최종 문자열 하나보다 값 + 출처 + 적용 대상 + 버전 + 상태를 한 묶음으로 저장하자.

피드백 활용은 과거 제안과 현재 범위를 구분해. 이 가이드의 원래 제안에는 후속 조회 참조와 사전 개선이 있었지만, 현재는 수정을 원본과 분리해 저장하고 명시적 요청의 새 실행에서만 재검토해. 같은 대상이라는 이유로 자동 반영하거나, 다른 작업의 추론·RAG·학습에 사용하지 않아. 자동 명령 재전송도 하지 않아.

09 / PROOF OF CONCEPT

정확도보다 먼저, 비교 가능한 실험을 만들자

[추론] 첫 PoC는 한 공정 · 한 표기 규칙 · 제한된 작업 후보에 집중하자. 같은 이미지 집합에서 맥락이 언제 도움이 되고 언제 해가 되는지를 보이는 게 핵심이야.

비교 조건보여줄 것평가 질문
A · 이미지 + 공통 규칙부재별 계획·이력 없이 해석인식·일반 문법만으로 어디까지 가능한가?
B · A + 유효한 맥락대상이 확인된 도면·작업·이력 사용의미 해석과 처리 가능 비율이 실제로 좋아지는가?
C · A + 잘못된 맥락다른 부재·구버전·충돌 정보 주입틀린 맥락에 끌려 자동 확정하는가, 충돌을 잡는가?
D · 맥락 일부 누락ID·문서·상태 중 일부 제거미확정 항목을 정확히 짚고 필요한 질문을 하는가?
지표분모까지 정의하기
의미 항목 정확도정답인 의미 항목 수 / 평가한 의미 항목 수. 부재·치수 종류·값·단위·방향 등을 구분.
잘못된 자동 확정률틀린 자동 확정 건수 / 자동 확정 건수. 자동 확정이 0건이면 비율은 해당 없음으로 표시.
자동 처리율사람 개입 없이 확정한 건수 / 전체 건수. 후보 추천만 한 건을 확정에 포함하지 않음.
위험 사례 확인 요청 재현율사람에게 보낸 위험 사례 수 / 정답상 확인이 필요한 위험 사례 수.
작업자 검토 부담확인 건수, 확인에 걸린 시간, 잘못된 추천을 승인한 사례를 함께 기록.

[추론] 개발 자료와 평가는 부재·원본 이미지 단위로 분리하고, 평가 정답이 확인 이력에 미리 들어가지 않게 하자. 사례 수와 분모를 함께 공개하고, 합성 자료의 결과를 현장 정확도로 말하지 않아. 자동 확정 정책을 아직 검증하지 못했다면 후보 추천·사람 확인만 시연해도 돼.

목적함수로 표현하면

[추론] “잘못된 확정의 비용 + 사람 검토 비용 + 처리 지연”을 줄이되, 필수 근거 누락·기준 충돌 시 확정 금지 같은 제약을 둬. 바꿀 수 있는 것은 확인 임계값·후보 수·질문 방식·검토 순서이고, 임의로 바꾸면 안 되는 것은 승인 기준·재료의 사실·원본 관찰이야. 비용 비율과 허용 오류 수준은 멘토와 정할 항목이야.

작업자 확인 화면에 담을 최소 정보

  1. 원본 영역과 주변 장면: 무엇을 읽었고 어느 부재인지.
  2. 대안 후보: a6/a8처럼 차이가 나는 항목을 선명하게 표시.
  3. 맥락의 출처: 부재 연결 근거, 도면·WPS 버전과 해당 항목.
  4. 확인 이유: 인식 모호 / 대상 미식별 / 기준 충돌 / 필수 정보 누락.
  5. 결정과 범위: 승인·수정·보류, 현재 작업에만 적용할지, 추가 근거가 필요한지.

멘토에게 우선 확인할 여섯 가지

  1. 한 장면 확보: 실제 사진과 그 사진의 올바른 작업 해석을 함께 볼 수 있는가?
  2. 표기 규칙: 표준 기호와 자체 약어의 비율, 덧쓰기·취소 표기의 규칙은 무엇인가?
  3. 대상 식별: 부재·용접부 ID를 촬영 시점에 어떻게 알 수 있는가?
  4. 기준 자료: 도면·작업지시·WPS 중 무엇을 제공하며 개정·변경 승인은 어떻게 관리하는가?
  5. 자동화 경계: 조건 후보, 프로그램 선택, 실제 제어 중 어디까지가 평가 대상인가?
  6. 실패 비용: 무엇을 반드시 사람에게 보내야 하며, 정답 판정과 승인은 누가 하는가?

과거 spike-demo와 현재 dev는 달라. 10월 5일에 참고한 spike-demo에는 합성 사례·사진 OCR 연결·시연 규칙·확인 이력·내보내기가 있었지만 현재 dev로 승계하지 않았어. 현재 제품 기능은 후보 → 유효 작업지시 연결 CLI이고, 별도 실험은 개발 표본 레포트를 봐. 이 가이드의 전체 흐름·현장 성능을 구현 완료로 취급하지 않아.

10 / RECOMMENDATION

제안하는 맥락의 방향성

“현재 작업에 연결할 수 있는 근거만 사용하고,
근거가 부족하거나 충돌하면 무엇을 확인해야 하는지 알려주는 시스템.”

[추론] 우리의 차별점은 LLM이 문서를 많이 읽는다는 데 두기보다, 사진 속 표기와 작업 문서를 올바르게 연결하고, 그 연결이 틀릴 가능성까지 다룬다는 데 두는 게 좋아.

입력은 열린 구조

사진만 받아도 후보를 만들고, ID·작업지시가 들어오면 확인된 범위만큼 맥락을 확장해. MES가 반드시 있어야만 작동하는 구조로 시작하지 않아.

판정은 근거를 통과하는 구조

대상·버전·적용 범위를 먼저 검사하고 후보를 비교해. 규칙 충돌을 높은 비전 점수나 문서 유사도로 상쇄하지 않아.

사람의 개입은 구체적인 질문

“확인하세요” 대신 “부재가 맞는지”, “도면 개정이 맞는지”, “a6인지 a8인지”처럼 미해결 항목을 좁혀서 보여줘.

현재는 수정 저장과 명시적 재검토

사람의 수정을 원본·근거·대상·버전과 함께 별도 저장해. 명시적 요청은 새 실행으로 남기고, 다른 작업의 자동 참조·학습·명령 재전송은 하지 않아.

첫 구현 단위: 실제 장면 하나의 사진 → 표기 후보 → 대상 연결 → 기준 대조 → 후보 또는 확인 → 추적 가능한 출력을 끝까지 만들자. 그 장면에서 맥락이 없을 때와 틀릴 때도 보여줘야 방향성이 검증돼.

7분 발표의 중심 문장: “우리는 표기를 읽는 데서 멈추지 않고, 적용 가능한 작업 근거와 연결해 조건 후보를 제시하며, 불확실한 연결은 작업자의 구체적인 확인으로 해결합니다.”
