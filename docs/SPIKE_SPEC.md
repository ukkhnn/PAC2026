# ContextWeld spike 범위

이 spike는 현장 자료가 없는 상태에서 판단 흐름과 작업자 확인을 검증하는 로컬 프로토타입이다. 실제 조선소의 표기·WPS를 재현하거나 로봇을 제어하지 않는다.

## 시연 입력

가상 부재 `BLK-017`, 이음부 `S-04`에 대해 `PART`, `SEAM`, `WELD`, `SIZE`, `POS` 라벨을 사용한다. `FW`·`BW`와 숫자는 시연 문법이며 실제 현장 약어 사전이 아니다. 사진·표기 후보·작업계획·기준의 출처를 구분한다.

## 검증할 동작

| 사례 | 입력 | 기대 동작 |
|---|---|---|
| 정상 | SIZE 6, 계획 6 | 적용 범위와 일치하는 시연용 프로그램 후보 |
| 모호 | SIZE 6 또는 8, 계획 6 | 후보를 6으로 좁히되 작업자 확인 필요 |
| 충돌 | SIZE 8, 계획 6 | 시각 결과를 6으로 덮어쓰지 않고 보류 |
| 이력 | 동일 작업의 모호한 표기, 치수 계획 누락 | 동일 범위에서 확인한 해석만 참조 |
| 잘못된 맥락 | 사진과 계획의 부재 불일치 | 조건 후보 확정 및 승인 차단 |

예제의 인식 후보는 미리 작성한 시연 데이터다. 업로드 사진의 OCR 결과와 구분한다. 결과를 설명하기 위한 사례이며 독립적인 현장 성능 평가셋이 아니다.

## 조건과 근거

프로그램 후보는 `DEMO-FW6`, `DEMO-FW8`이다. 재질·두께·자세·작업 종류와 치수가 일치할 때만 후보를 연결한다. 전류·전압·이동속도는 원본 WPS가 없으므로 `null`로 남긴다. 작업자 승인도 시연 결과 확인을 뜻하며 실제 용접 실행 승인이 아니다.

근거 검색은 소규모 시연 규칙의 키워드 조회다. 임베딩 기반 RAG나 VLM 의미 추론은 후속 교체 범위다. 인간 확인 이력은 부재·이음부·재질·두께·자세·계획 버전·규칙 버전이 같은 범위에만 적용한다.

## 기술 구성

Python 표준 라이브러리의 HTTP 서버·SQLite와 HTML/CSS/JavaScript를 사용한다. API 키와 외부 패키지 설치 없이 실행한다. macOS에서는 Swift와 Apple Vision을 사용할 수 있을 때 업로드 이미지의 실제 OCR을 실행한다. OCR이 불가능한 경우 오류를 표시하며 모의 결과로 대체하지 않는다.

입력 관측, 맥락, 규칙, 결정, 확인 이력을 각각 보존한다. 화면과 서버, 인식 어댑터, 판단 엔진, 저장소를 분리해 멘토링 이후 교체할 수 있게 한다.

## OCR 구현 참고

Apple Vision의 [VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)와 [이미지 문자 인식 안내](https://developer.apple.com/documentation/vision/recognizing-text-in-images)를 참고한다. `vision_ocr.swift`는 실제 인식 후보와 신뢰 점수, 영역 좌표를 반환하며 서버는 원본과 함께 저장한다.
