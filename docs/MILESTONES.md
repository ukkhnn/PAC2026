# ContextWeld 마일스톤

기준일: **2026-10-10**. 현재 범위는 [데모 스펙 v1.4](DEMO_SPEC.md), [OCR 구성 v1.2](OCR_PIPELINE_SPEC.md), [문서 적용 계획 v1.3](DOCUMENT_APPLICATION_PLAN.md)을 따른다. 아래 현재 범위별 완료 기준과 **논의용 작업 분할안**을 구분한다. 새 일정·소요 시간·세부 분할은 아직 확정하지 않았다.

단일 반사·재촬영 시나리오를 Runpod에서 실행·저장하고 로컬 관리자 화면에서 재생한다. **아이디어 피칭을 위한 전체 흐름과 설명 가능한 근거가 우선이다.** 인식·관계·문서 처리는 데모 입력으로 동작을 확인하고, 높은 정확도·독립 평가·엄밀한 모델 비교는 완료 조건으로 요구하지 않는다. 10월 2일에 작성한 과거 날짜별 로드맵은 현재 실행 계획에서 제거했다. 과거 계획은 Git 이력에 남으며 대회 일정의 원문은 [참고 자료](SOURCES.md)에서 확인한다.

## 1. 실제 준비 상태

| 구분 | 확인된 상태 | 아직 확인되지 않은 것 |
|---|---|---|
| 공통 명세 | 범위·데이터 계약과 문서 검토용 모사 작업·도면·범위 전달 프로파일 고정 | 최종 A/B 표기·기호·이음과 실제 작업 적용조건 |
| 제품 코드 | 공개 사진 10장 OCR/VLM·50결과, 원문 4개 74청크 검색. 실제 관측→모사 작업문서→WPS 범위→HTTP 모의 수신 연결. [문서 연결 실행](DOCUMENT_DEMO.md) | A/B 시나리오·실제 작업/WPS 적용·수정 재검토·관리자 화면 |
| 기존 실험 | 공개 이미지 OCR·짧은 문서 제공·출력 검사 파일럿 보존 | 새 실행은 기능 연결 확인이며 정확도 비교/평가 완료가 아님 |
| Runpod 환경 | [Pod v1](POD_VER1.md)의 GPU/Vulkan·Isaac 6.1 호환성 앱 기동 기록 | 전체 앱·센서 RGB·로봇 카메라·ROS/Foxglove 통합 |
| 입력·근거 자료 | 사진·원문 해시와 원문 위치 검색 보존. LANL WPS Rev.1의 선택 헤더·대표층 1을 원문 렌더와 전사 대조, 모사 작업지시·도면 작성 | 나머지 층·단위 미확정 필드·사람의 적용 검토, 사진의 실제 재질·두께·이음 및 로봇 적용성 |
| 문서 연결 확인 | 서버 정상 1건은 `succeeded`·`received`; 누락·공정 충돌·개정 불일치·실제 판독 불일치 4건은 `needs_review`·전송 차단. 양환경 테스트 각 59개 통과 | 문서 범위 검토 밖의 물리적 적합성·작업 승인·전체 데모 완료 |

환경의 일부 확인이나 문서 작성만으로 아래 구현 단계를 완료로 표시하지 않는다.

## 2. 현재 범위별 완료 기준

[데모 스펙](DEMO_SPEC.md) 12절의 P0~P5를 추적한다. 이 표는 작업을 반드시 직렬로 실행하라는 의미가 아니다.

| 단계 | 완료 시 남길 결과 | 현재 상태 |
|---|---|---|
| P0 장면·입출력 | 마킹/대상 정답, 등록된 원문·조건표, 문서 적용범위, 모의 필드 | 부분 구현: 문서 검토용 모사 작업·범위 필드 고정. 최종 A/B 장면·기호·실제 적용조건 미완료 |
| P1 RGB 생성 | 동일 장면에서 시점만 달리한 A/B RGB와 촬영 설정 | 미완료 |
| P2 인식·해석·전달 | 실제 OCR/VLM·관계·정확 조회/RAG·검증·모의 ACK, 수정 저장·명시적 재검토 | 부분 구현: 실제 관측·모사 문서·WPS 범위 검사·모의 ACK 완료. A/B 관계·재촬영·수정 재검토 미완료 |
| P3 저장·로컬 재생 | 내보낸 실행 묶음, 해시 확인, 서버 없이 조회·재생하는 관리자 화면 | 부분 구현: 인식·문서 검토 묶음과 검증기. 전체 시나리오·재검토 묶음·관리자 화면 미완료 |
| P4 재촬영 연동 | 실제 인식 요청 → 팔 이동 → 새 RGB → 재추론의 연결 증거 | 미완료 |
| P5 영상·인계 | 선택한 시연 수준의 영상, 환경·실행·재생 안내, 실패·한계 보고 | 미완료 |

사전 촬영 방식은 P1~P3의 첫 구현 및 허용 대안이다. P4를 통과해야 실제 재촬영 연동 완료로 표시한다. 최종 시연 수준은 데모 스펙 O08에서 결정한다. 수정 기록은 저장만으로 모델에 재사용하지 않으며 명시적 재검토는 별도 실행이다.

## 3. 마일스톤 분할 제안 — 논의 전 초안

`[추론]` 기존 P2에 인식·문서·검증·전달이 몰려 있어 실패 원인을 구분하기 어렵다. 인식과 문서 기반을 나누고, 시뮬레이터와 병렬로 검증하는 아래 분할을 제안한다. M 번호는 **아직 채택되지 않은 작업안**이며 위 P 번호를 대체하지 않는다.

| 제안 | 할 일 | 완료를 판단할 증거 | 대응 범위 |
|---|---|---|---|
| M0 입력·근거 준비 | 지원 표기·대상·최종 필드를 정하고 원문 등록·표 검수·데모 기대값 준비 | 사진의 표기가 어떤 문서·표 행·출력 필드로 이어질지 추적 가능 | P0 |
| M1 인식·관계 연결 | PP-OCRv6 medium+Qwen3-VL-8B로 데모 표기·기호/대상 관계를 실제 추론 | 실제 입력·출력과 필요한 필드 확인. 오류가 진행을 막을 때만 구성 보완 | P2 일부 |
| M2 문서·조건 연결 | 작업·개정 정확 조회, 범위 제한 RAG, WPS 조건·단위 검사 | 올바른 근거 문단/표 행 조회, 잘못된 대상·개정·적용조건의 배제 | P2 일부 |
| M3 시뮬레이션 촬영 | RGB 한 장부터 시작해 동일 장면의 A/B·손목 카메라 구성 | 실제 센서 이미지·자세·설정, A/B에서 관측 가능성 차이 | P1 |
| M4 전체 흐름·기록 | 사전 촬영 A/B로 재촬영 분기→해석→검증→모의 전달→내보내기 연결. 수정 저장·명시적 재검토도 구현 | 요청·관측·근거·명령·ACK의 연결과 손상 검사. 선택 수정의 새 실행·원본 불변·전달 별도 요청 확인 | P2 완료·P3 일부 |
| M5 관리자 재생 | 원본·타임라인·근거·전달·수정 기록의 로컬 조회 | 서버·인터넷 없이 동일 묶음의 반복 재생, 추론/명령 호출 없음 | P3 완료 |
| M6 카메라 연동 | 인식 요청으로 팔 이동 후 새 프레임을 받아 실제 재추론 | 요청 ID·이동 완료·촬영 시각 연결, 실패/오래된 프레임 배제 | P4 |
| M7 시연 확인·녹화·인계 | 시나리오 재실행, 한계 정리, 영상·실행 안내 | 실제 결과와 화면 설명 일치, 로컬 보관·재생 재현 | P5 |

### 의존성과 병렬 진행

- M0의 최소 표기·필드·데모 기대값부터 정한다. 원문 적재와 검수가 모두 끝나기 전에도 독립적인 OCR·RGB 실행 가능성을 먼저 확인할 수 있다.
- M1·M2·M3는 병렬 진행한다. M1은 기존 Steel OCR 사진으로 먼저 연결할 수 있고 M2의 문서 연결도 시뮬레이션 완성을 기다리지 않는다.
- M4는 실제 A/B와 인식·문서 결과를 받아 통합한다. M5는 미리 합의한 실행 묶음 예제로 골격을 만들 수 있지만, 완료 판정은 M4의 실제 기록으로 한다.
- M6는 M4의 요청·촬영 계약 위에 연결하므로 관리자 화면 완성을 기다릴 필요는 없다. M5와 병렬로 진행할 수 있다.
- 시연에 필요한 입력·기대 흐름은 M0에서 정한다. M7은 실제 실행과 녹화 내용의 일치를 확인하며, 뒤늦게 독립 성능 평가를 필수로 추가하지 않는다.

### 세분화 확정 전에 남은 결정

- 최종 A/B 시나리오에 쓸 표기·기호·이음·작업문서. 현재 문서 검토용 모사 작업·WPS 범위 필드와 실제 장면의 적용조건을 구분한다.
- 데모에 쓸 사진·마킹과 기대 흐름. 기존 Steel OCR부터 활용하며 추가 데이터는 필요한 경우에만 확보한다. 정확도 목표와 별도 평가셋은 선행 결정 항목이 아니다.
- 수정·명시적 재검토 입력 위치. 읽기 전용 관리자 재생과 구분하며 M4/M5 구현 전에 결정한다.
- 실제 재촬영 연동을 최종 영상에 포함할지와 관리자 UI/Foxglove의 역할.

검색기·임베딩·UI 도구의 이름을 모두 고른 뒤에야 착수할 필요는 없다. 입력·근거·출력 계약을 먼저 고정하고 작은 검증 결과로 선택한다.
