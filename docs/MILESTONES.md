# ContextWeld 마일스톤

기준일: **2026-10-10**. 현재 범위는 [데모 스펙 v1.5](DEMO_SPEC.md), [OCR 구성 v1.2](OCR_PIPELINE_SPEC.md), [문서 적용 계획 v1.3](DOCUMENT_APPLICATION_PLAN.md)을 따른다. 아래 현재 범위별 완료 기준과 **논의용 작업 분할안**을 구분한다. 새 일정·소요 시간·세부 분할은 아직 확정하지 않았다.

단일 반사·재촬영 시나리오를 Runpod에서 실행·저장하고 로컬 관리자 화면에서 재생한다. **아이디어 피칭을 위한 전체 흐름과 설명 가능한 근거가 우선이다.** 인식·관계·문서 처리는 데모 입력으로 동작을 확인하고, 높은 정확도·독립 평가·엄밀한 모델 비교는 완료 조건으로 요구하지 않는다. 10월 2일에 작성한 과거 날짜별 로드맵은 현재 실행 계획에서 제거했다. 과거 계획은 Git 이력에 남으며 대회 일정의 원문은 [참고 자료](SOURCES.md)에서 확인한다.

## 2. 현재 범위별 완료 기준

[데모 스펙](DEMO_SPEC.md) 12절의 P0~P5를 추적한다. 이 표는 작업을 반드시 직렬로 실행하라는 의미가 아니다.

| 단계 | 완료 시 남길 결과 | 현재 상태 |
|---|---|---|
| P0 장면·입출력 | 마킹/대상 정답, 등록된 원문·조건표, 문서 적용범위, 모의 필드 | 부분 구현: 문서 검토용 모사 작업·범위 필드, 기존 작업대와 새 조선소 수기 장면 고정. 장면의 부재·이음과 작업문서 연결 및 통합 적용조건 미완료 |
| P1 RGB 생성 | 동일 장면에서 시점만 달리한 A/B RGB와 촬영 설정 | 달성: 기존 작업대 live-01과 조선소 수기 live-03의 UR10 손목 A/B·고정 반사·원본 RGB·Foxglove 수신 확인. 기존 설정·출력 보존 |
| P2 인식·해석·전달 | 실제 OCR/VLM·관계·정확 조회/RAG·검증·모의 ACK, 수정 저장·명시적 재검토 | 부분 구현: 실제 관측·모사 문서·WPS 범위 검사·모의 ACK 완료. 수정 저장·명시적 재검토·선택적 전달은 문서 범위 규칙 재검토로 구현·서버 실행. A/B 관계·재촬영·시각 관계 재해석 미완료 |
| P3 저장·로컬 재생 | 내보낸 실행 묶음, 해시 확인, 서버 없이 조회·재생하는 관리자 화면 | 부분 구현: 인식·문서 검토·재검토 묶음과 검증기, 문서·재검토 한 건의 오프라인 HTML 조회 완료. 시각 검수·여러 실행 통합·A/B 재생·전체 관리자 미완료 |
| P4 재촬영 연동 | 실제 인식 요청 → 팔 이동 → 새 RGB → 재추론의 연결 증거 | 미완료 |
| P5 영상·인계 | 선택한 시연 수준의 영상, 환경·실행·재생 안내, 실패·한계 보고 | 미완료 |

사전 촬영 방식은 P1~P3의 첫 구현 및 허용 대안이다. P4를 통과해야 실제 재촬영 연동 완료로 표시한다. 최종 시연 수준은 데모 스펙 O08에서 결정한다. 수정 기록은 저장만으로 모델에 재사용하지 않으며 명시적 재검토는 별도 실행이다. [명시적 재검토](EXPLICIT_REVIEW.md)는 공개 사진 기반 문서 범위에서 구현했고 A/B 시나리오 통합은 M4 범위로 남는다.

## 3. 마일스톤 분할 제안 — 논의 전 초안

`[추론]` 기존 P2에 인식·문서·검증·전달이 몰려 있어 실패 원인을 구분하기 어렵다. 인식과 문서 기반을 나누고, 시뮬레이터와 병렬로 검증하는 아래 분할을 제안한다. M 번호는 **아직 채택되지 않은 작업안**이며 위 P 번호를 대체하지 않는다.

### 의존성과 병렬 진행

- M0의 최소 표기·필드·데모 기대값부터 정한다. 원문 적재와 검수가 모두 끝나기 전에도 독립적인 OCR·RGB 실행 가능성을 먼저 확인할 수 있다.
- M1·M2·M3는 병렬 진행한다. M1은 기존 Steel OCR 사진으로 먼저 연결할 수 있고 M2의 문서 연결도 시뮬레이션 완성을 기다리지 않는다.
- M4는 실제 A/B와 인식·문서 결과를 받아 통합한다. M5는 미리 합의한 실행 묶음 예제로 골격을 만들 수 있지만, 완료 판정은 M4의 실제 기록으로 한다.
- M6는 M4의 요청·촬영 계약 위에 연결하므로 관리자 화면 완성을 기다릴 필요는 없다. M5와 병렬로 진행할 수 있다.
- 시연에 필요한 입력·기대 흐름은 M0에서 정한다. M7은 실제 실행과 녹화 내용의 일치를 확인하며, 뒤늦게 독립 성능 평가를 필수로 추가하지 않는다.

### 세분화 확정 전에 남은 결정

- 조선소 수직 강판·중앙 수기 메모의 형상과 A/B 촬영 구성은 완료했다. 남은 결정은 이 장면의 합성 부재·`J01`·화살표를 작업문서에 연결하는 방식이다. 현재 문서 검토용 모사 작업·WPS 범위 필드와 장면의 적용조건을 구분한다.
- 데모에 쓸 사진·마킹과 기대 흐름. 기존 Steel OCR부터 활용하며 추가 데이터는 필요한 경우에만 확보한다. 정확도 목표와 별도 평가셋은 선행 결정 항목이 아니다.
- ~~수정·명시적 재검토 입력 위치~~ → 2026-10-10 서버 CLI·JSON 요청으로 결정(데모 스펙 O07). 읽기 전용 관리자 재생과 분리한다. 영상에 수정 장면을 넣을지는 미정.
- 실제 재촬영 연동을 최종 영상에 포함할지와 관리자 UI/Foxglove의 역할.

검색기·임베딩·UI 도구의 이름을 모두 고른 뒤에야 착수할 필요는 없다. 입력·근거·출력 계약을 먼저 고정하고 작은 검증 결과로 선택한다.
