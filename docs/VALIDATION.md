# Spike 검증 기록

기준일: 2026-10-02. 대상은 로컬 spike이며 현장 성능·안전성 검증 결과가 아니다.

## 자동 검증

Python 3.11.9에서 `python3 -m unittest discover -s tests -v`의 17개 테스트가 통과했다. Python 표준 라이브러리만 사용했다.

| 검증 범위 | 확인 내용 |
|---|---|
| 판단 | 정상 후보, 모호 후보 좁힘, 낮은 점수의 확인 요청, 치수 누락 시 생성 금지 |
| 맥락 | 단일 인식과 계획의 충돌 보존, 다른 부재의 계획 차단, 선행작업 미확인·기준 범위 밖 두께의 후보 차단 |
| 기억 | 같은 작업 범위·계획 버전에서만 적용, 새 후보 밖의 값 적용 금지, 보류 이력 제외 |
| 확인·저장 | 사람 수정과 원본·기존 해석 분리, 이유 저장, 오래된 분석 버전의 수정 거부 |
| HTTP 연결 | 분석→확인→새 분석 이력 연결, 변경 계획에서 이력 제외, 원본을 보존한 수정 |
| 입력·로컬 접근 | 잘못된 이미지·비유한 숫자·잘못된 맥락 형식 거부, 외부 Origin 요청과 내부 파일 접근 거부 |

Node.js 22.19에서 `node --check src/contextweld/web/app.js`가 통과했다. 실제 현장 정확도·지연시간·부하·다중 사용자 운용은 측정하지 않았다.

## 실제 OCR 연결

macOS Swift 6.1.2와 Apple Vision으로 합성 인쇄체 PNG의 라벨 5개를 읽었다. 실제 인식 결과를 파서와 맥락 판정에 전달해 `BLK-017 / S-04 / FILLET / 6 / FLAT`, `DEMO-FW6` 시연 후보로 연결했다. `python3 scripts/check_ocr.py`로 같은 검사를 실행할 수 있다.

이것은 실제 OCR 경로의 연결 시험 1건이다. 수기·오염·반사·훼손·조선소 현장 표기를 검증한 결과가 아니며, 점수 1.00도 정답률 100%를 의미하지 않는다. 실제 이미지 업로드 기능은 환경에 따라 OCR 도구를 처음 컴파일하는 시간이 추가된다.

## 브라우저 검증

실제 로컬 화면에서 정상·모호·충돌·확인 이력·계획 버전 변경을 실행했다. 모호 후보의 전후 비교, 이유를 남긴 확인, 후속 이력 적용, 계획 버전 변경 후 보류, 해결되지 않은 충돌의 확인 거부, 보류 이유 저장, PNG 업로드의 실제 OCR 관측과 분석 연결, 저장된 이력 재조회, 판단 JSON 파일 다운로드를 확인했다.
