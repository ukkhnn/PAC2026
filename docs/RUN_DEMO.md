# 로컬 데모 실행

## 필요한 환경

시연 사례와 확인 이력 기능은 Python 3.10 이상과 브라우저로 실행한다. 외부 패키지·API 키·외부 서버는 필요하지 않다. 실제 사진 OCR은 macOS, `swiftc`로 실행 가능한 Swift 개발 도구, Apple Vision이 추가로 필요하다. macOS에서 Swift를 쓸 수 없거나 다른 OS인 경우 시연 사례는 동작하지만 사진 OCR은 사용할 수 없다.

저장소 루트에서 실행한다.

```sh
python3 scripts/run_demo.py
```

브라우저에서 <http://127.0.0.1:8765>를 연다. 종료는 실행한 터미널에서 Ctrl+C다. 포트를 이미 사용한다면 `python3 scripts/run_demo.py --port 8766`으로 실행하고 해당 포트를 연다. 서버는 이 컴퓨터의 루프백 주소에만 연결된다. 인터넷에 배포하는 용도의 서버가 아니다.

## 5분 시연 순서

| 순서 | 화면 조작 | 관찰할 결과 |
|---|---|---|
| 1 | 정상 표기 선택 → 분석 | `DEMO-FW6` 시연 후보, 실제 용접 수치는 미정 |
| 2 | 모호한 표기 선택 → 분석 | 표기만으로는 6/8 미확정, 작업계획으로 6 후보, 원본 확인 요청 |
| 3 | 원본 확인 이유 입력 → 결과 확인 | 확인 이력과 이유 저장 |
| 4 | 확인 이력 재사용 선택 → 분석 | 계획 치수 없이 같은 작업의 이력으로 후보를 좁힘; 새 입력의 확인은 여전히 필요 |
| 5 | 계획 버전을 `PLAN-DEMO-v2`로 변경 → 재분석 | 이전 이력을 적용하지 않고 판단 보류 |
| 6 | 작업계획 충돌 선택 → 분석 | 이미지 치수 8 보존, 계획 6과 충돌하여 조건 후보 차단 |
| 7 | 이유 입력 → 보류 기록 | 보류 이력 저장; 확인 이력으로 재사용하지 않음 |
| 8 | 다른 부재의 계획 선택 → 분석 | 이미지와 계획의 부재 불일치 검출 |
| 9 | 확인 이력 화면에서 기록 선택 → 판단 기록 JSON | 원본 후보·맥락·규칙 버전·판단·수정·확인 이유 확인 및 내보내기 |

치수 수정 동작을 살펴보려면 충돌 사례에서 치수 수정에 `6`을 입력하고 원본 재확인 이유를 남긴다. 확인 후에도 원본 `SIZE: 8`과 표기만 해석한 결과는 그대로 남으며, 수정된 판단만 별도로 표시된다. 이것은 감사 이력을 위한 가상 시험이다. 실제 사진의 8을 임의로 6으로 바꾸라는 작업 지침이 아니다.

## 실제 OCR 확인

`사진 넣기`에서 `data/examples/ocr-printed.png`를 선택한다. 가상의 라벨 5개를 인쇄체로 만든 연결 시험 이미지이며 현장 사진·수기 표기가 아니다. 처음에는 OCR 도구를 컴파일하므로 시간이 더 걸릴 수 있다. 이후 같은 도구를 재사용한다.

완료 후 `업로드 사진 · 실제 Apple Vision OCR` 배지와 관측 영역이 나타난다. 맥락을 다음과 같이 맞추고 분석한다.

| 입력 | 값 |
|---|---|
| 부재 / 이음부 | BLK-017 / S-04 |
| 계획 치수 / 작업 종류 | 6 / FILLET |
| 재질 / 판 두께 / 자세 | DEMO-STEEL / 12 / FLAT |
| 계획 버전 / 선행작업 | PLAN-DEMO-v1 / 완료 정보 있음 |

업로드 사진은 자동으로 작업계획을 찾아주지 않는다. 화면에 남아 있는 맥락이 새 사진에 맞는지 확인해야 한다. OCR은 영문·숫자 기반으로 설정돼 있고, 의미 파서는 `PART`, `SEAM`, `WELD`, `SIZE`, `POS`의 시연 문법만 지원한다. 현장 기호·약어·자유로운 수기에 대한 인식·해석 성능은 검증하지 않았다.

## 저장과 재시작

분석·확인 기록은 `.local/contextweld.sqlite3`, 업로드 이미지와 인식 결과는 `.local/uploads/`, OCR 실행 파일과 컴파일 캐시는 `.local/`에 저장한다. 모두 Git 추적에서 제외한다. 서버를 재시작해도 기록은 유지된다. 시연을 빈 이력으로 시작하려면 서버 종료 후 `.local/contextweld.sqlite3`를 다른 위치로 옮겨 보관하고 다시 실행한다. 이때 새 DB가 생성된다. 원본 이미지와 내보낸 JSON도 작업 데이터이므로 필요한 자료만 공유한다.

## 검증 실행

```sh
python3 -m unittest discover -s tests -v
node --check src/contextweld/web/app.js
python3 scripts/check_ocr.py
```

첫 명령은 판단·저장·로컬 HTTP API 테스트다. 두 번째는 Node.js가 설치된 경우 화면 코드의 문법을 확인한다. 세 번째는 macOS의 실제 OCR 연결 시험이며 플랫폼 조건이 필요하다. 자동 테스트에 실제 OCR을 포함하지 않아 다른 OS에서도 판단·API 테스트를 실행할 수 있다. 제한된 실행 환경은 로컬 포트 연결 또는 Vision 실행을 막을 수 있다.

## 오류 대응

| 증상 | 확인할 사항 |
|---|---|
| 화면이 열리지 않음 | 서버가 실행 중인지, 포트와 화면 주소가 같은지 확인 |
| 첫 업로드가 오래 걸림 | Swift 컴파일 중일 수 있음. 실패하면 화면에 오류가 표시됨 |
| 실제 OCR 사용 불가 | macOS와 `swiftc` 실행 환경 확인. 예시 시연은 계속 사용 가능 |
| 이미지 오류 | 8 MB 이하 PNG/JPEG, 정상 이미지인지 확인 |
| 문자 0개 또는 해석 누락 | 표기가 선명한지, 시연 문법과 일치하는지 확인. 결과를 임의 생성하지 않음 |
| 동일 이력이 적용되지 않음 | 결과 확인 여부와 부재·이음부·재질·두께·자세·계획·규칙 버전 일치 여부 확인 |
