## 다음 한 묶음

실행 결과는 [통합 레포트](REPORT-2026-10-09.md)에 있다. 현재는 인식의 정확한 식별자 확보가 가장 큰 병목이다.

1. 기존 10장과 다른 원본 묶음의 작은 개발 표본을 마련하고 문자 라벨·촬영 방향·부재번호 문법을 확인한다. 최종 테스트 분할은 아직 사용하지 않는다.
2. 필요한 경우 수기 인식 또는 VLM 대안을 한 가지 비교한다. 이번 오류를 보고 I/1 등을 정답에 맞춰 강제 교정하지 않는다.
3. 문서 쪽은 현재 140단어 자료집 전문 제공을 기준선으로 둔다. 실제 긴 문서·표·충돌 사례를 확보할 때 E3의 검색/분할 실험을 진행한다.
4. 제품 통합은 원본·후보·거절 이유·출처를 보여주는 확인 흐름을 우선한다. 구조 검사를 통과한 답변도 의미 정답이나 실행 승인으로 취급하지 않는다.
5. 기업 자료나 운영 절차가 생기기 전에는 실제 작업자 이력 효과 E6와 현장 통합 성능 E7을 주장하지 않는다.

자료·모델·프롬프트 선택은 아직 최종 확정이 아니다. 작은 개발 관찰을 근거로 다음 질문을 좁힌 상태다.

## 실험을 시작할 때

질문, 사용할 자료와 출처, 고정 조건, 바꾸는 요소, 채점법을 짧게 기록한다. 표본·라벨·설정은 버전 또는 해시로 식별한다. 기존 평가 자산을 수정하지 않고 새 실험으로 확장한다.

## 실험을 끝낼 때

원본 출력과 실패, 맞힌 수/전체 수, 환경·시간, 검증, 유지·교체·보류 결정을 [레포트 양식](REPORT_TEMPLATE.md)에 남긴다. 한계를 적고 다음 질문 하나를 고른다. 해보지 않은 비교는 미측정으로 남긴다.
