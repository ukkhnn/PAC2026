# E1-002 — 네 방향 OCR 결과

2026-10-09 · 실행 완료. 표본과 평가 규칙은 [프로토콜](PROTOCOL.md)에 고정했다.

## 결론

**네 방향을 합쳐도 정답 문자열을 포함한 후보가 0/28이었다.** 위치 대응은 늘었지만 정확한 식별자를 얻지 못했고, 후보 수와 처리량이 늘었다. 현재 Vision에 단순 회전만 추가하는 방식을 우선 개선안으로 채택하지 않는다.

## 해석과 한계

각 회전의 영역을 원래 좌표계로 되돌리고, 정답 대신 관측 간 IoU로 묶었다. 대표 후보는 confidence가 높은 순서이며 동점은 작은 회전각을 우선한다. confidence가 정답 확률이 아니라는 E1-001의 관찰 때문에 이 규칙은 비교를 위한 임시 규칙이다. 정답을 보고 회전이나 문자를 고르지 않았다.

각 후보의 원문·점수·회전각·원래 관측 순위를 보존했다. top3와 전체 후보 포함률은 별도로 계산했다. 순위에 관계없이 정답이 없었으므로 대표 후보를 고르는 규칙만 바꿔도 해결된다는 근거는 없다. 전체 이미지와 정답 영역 crop 모두 같은 한계를 보였다.

이번 표본은 개발용 10장 중 채점 대상 9장·28개 표기다. 같은 이미지·부재의 종속성과 라벨 검수 한계는 E1-001과 같다. 문자 오류 합이 각각 4개 줄었지만 완전 일치 개선은 +0/28이다. 현장 성능으로 일반화하지 않는다.

## 검증·재현

- 회전 좌표의 정방향/역방향, 모서리 변환, 후보 보존·중복 제거, 떨어진 영역 분리 테스트 4개 통과.
- 이전 실험의 이미지·정답·코드·출력은 수정하지 않았다.
- 원문은 [raw.json](results/raw.json), 병합 근거는 [merged.json](results/merged.json), 대상별 결과는 [cases.json](results/cases.json), 집계는 [summary.json](results/summary.json)에 있다.

```sh
python3 -m unittest discover -s experiments/e1_rotation -p 'test_*.py' -v
python3 experiments/e1_rotation/run_rotation.py rerun-001
```

E1-001의 공개 입력과 컴파일된 Vision 실행 파일이 필요하다. 네이티브 Vision이 제한된 환경에서 실패하면 해당 실행 오류를 보존하고 macOS 로컬에서 재실행한다. 기존 실행 ID는 덮어쓰지 않는다.
