# E1-001 — 공개 철골 사진 OCR 진단 레포트

실행일: 2026-10-09 · 상태: 실행·검증 완료 · 성공 실행 ID: `2026-10-09-local`

## 결론

**이번 공개 개발 표본에서 Apple Vision의 부재번호 완전 일치는 전체 이미지와 정답 영역 crop 모두 0/28이었다. 영역만 잘라 주는 것으로는 인식 문제가 해결되지 않았다.**

정답 영역 제공 전후 문자 편집 오류는 206개에서 205개로 1개 줄었으나, 사례별로는 7개 개선·7개 악화·14개 동일했다. 이 정도 변화로 crop의 성능 우세를 주장하지 않는다. 현재 설정을 제품 인식기로 확정하지 않고, 방향 보정 또는 대안 인식기를 다음 비교 대상으로 남긴다. 다른 OCR/VLM과의 비교는 아직 수행하지 않았다.

## 결과

부재번호 정규화는 앞뒤 공백 제거와 대문자 변환만 사용했다. CER는 문자 편집 거리 합을 정답 문자 수 합으로 나눈 값이며 낮을수록 좋다. OCR 영역은 문자 정답과 무관하게 IoU 0.3 이상에서 일대일 대응했다.

| 지표 | 전체 이미지 | 정답 영역 crop | 해석·한계 |
|---|---:|---:|---|
| 문자 그대로 완전 일치 | 0/28 | 0/28 | 배포자 라벨 기준 |
| 정규화 후 완전 일치 | 0/28 | 0/28 | 변화 +0/28 |
| 상위 3개 후보 내 정답 | 0/28 | 0/28 | 요청은 최대 3개이며 실제 반환 수는 적을 수 있음 |
| 정답 영역에 대응된 OCR 영역 | 18/28 | 17/28 | 읽은 문자열이 맞았다는 뜻 아님 |
| 문자 편집 오류 / 정답 문자 | 206/280 | 205/280 | 총 오류 1개 감소 |
| CER | 73.57% | 73.21% | 0.36%p 차이, 독립 검증·유의성 검정 없음 |
| 부가 OCR 영역 수 | 18 | 1 | 다른 표기가 있어 모두 오검출로 단정할 수 없음 |
| 성공한 OCR 호출 | 10/10 | 28/28 | 성공 실행에서 API 오류 없음 |
| OCR 호출 시간 합 | 3.736초 | 2.179초 | 입력·호출 수가 다르고 최초 초기화 영향 존재 |
| 호출 시간 중앙값 | 0.258초 | 0.055초 | 속도 우열의 근거로 사용하지 않음 |

full 첫 호출은 1.498초였다. 다운로드·crop 생성·컴파일은 위 시간에서 제외했다. full 이후 crop 순서로 단 한 번 실행했으므로 시간은 재현 참고값이다. S10은 채점 대상이 없지만 full 호출 시간에는 포함된다.

## 실제 실패 사례

`∅`는 IoU 규칙에 맞는 OCR 영역이 없다는 뜻이며, 이미지 어디에서도 문자를 읽지 못했다는 뜻은 아니다.

| 사례 | 배포자 정답 | 전체 이미지 출력 | crop 출력 | 관찰 |
|---|---|---|---|---|
| S02-R00 | B1Sb30N-58 | BISD3ON-58 | BISb3ON-58 | crop에서 일부 문자가 개선됐지만 1/I·0/O 혼동 잔존 |
| S05-R00 | B1Sb30N-29 | BISb30N-29 | BISb30N-29 | 한 글자 차이도 다른 식별자가 될 수 있음 |
| S03-R01 | B1Sb30N-12 | ∅ | ∅ | 원본에서 세로 방향으로 놓인 표기. crop만으로 해결되지 않음 |
| S06-R05 | B1Sb30N-56 | BISbBoN-SG | BISb3oN-S6 | 편집 오류 5개 → 3개, 전체 정답은 여전히 아님 |
| S08-R04 | B1Sb40N-8 | ISB40N :8 | ∅ | crop에서 악화된 반례 |

영역 대응 임계값 때문에 정답 문자열이 버려졌는지도 확인했다. 동일 이미지 또는 해당 crop의 모든 관측·후보를 검색해도 배포자 정답과 정규화 후 일치한 문자열은 0/28이었다. 따라서 이번 완전 일치 0건을 IoU 임계값만으로 설명할 수는 없다.

대응된 출력 중 confidence가 1.0이면서 틀린 경우도 full 10건, crop 9건이었다. 이 점수를 그대로 정답 확률이나 자동 확정 기준으로 사용하면 안 된다.

## 자료·시각 검수와 한계

10장·29개 라벨을 확보했고 전체 crop 모음 및 S06·S10 원본을 직접 살펴봤다. 다방향 표기, 낮은 대비, 비스듬한 면과 가까이 있는 다른 표기가 보인다. 모든 라벨의 문자 의미를 도메인 전문가가 재검수한 것은 아니다. 채점은 배포자 라벨 그대로이며, label을 출력에 맞춰 수정하지 않았다.

S06 한 장의 표기 11개와 S08 한 장의 표기 7개가 합쳐 18/28을 차지한다. 여러 이미지가 같은 촬영 묶음·부재를 공유할 수 있으므로 표기 28개를 독립 현장 사례 28건으로 세면 안 된다. 배포자 학습 분할의 개발 탐색이며 조선소 수기 전체나 용접기호 성능으로 일반화할 수 없다.

자료는 [고정 버전의 데이터 카드](https://huggingface.co/datasets/iput-tk230215/steel-ocr-dataset-960/blob/37725284f40deeaccbdeb3734be7b0e90e974305/README.md)와 [학습 라벨](https://huggingface.co/datasets/iput-tk230215/steel-ocr-dataset-960/blob/37725284f40deeaccbdeb3734be7b0e90e974305/train_data/det/train.txt)에서 확보했다. 확인일은 2026-10-09다. 카드에는 MIT가 표시돼 있지만 별도 LICENSE 파일은 목록에 없었다. 원본·파생 이미지는 로컬에 보존하고 Git에서 제외했다. 외부 재배포는 수행하지 않았다.

카드는 train 222장을 설명하지만 고정 버전의 실제 train.txt는 156행이었다. 이번 표본 선정은 실제 156행을 기준으로 했다. 원본판 테스트 이미지 14개의 파일명과 선정 10장의 이름은 겹치지 않았다. [검사 기록](split-audit.json)은 파일명만 비교하므로 시각적으로 유사한 파생 자료까지 독립성을 보장하지 않는다. 테스트 이미지와 테스트 정답은 내려받지 않았다.

이미지 목록·정답·SHA-256은 [manifest.json](manifest.json), 실제 출력·전체 사례별 점수는 [results/raw.json](results/raw.json)과 [results/cases.json](results/cases.json), 집계는 [results/summary.json](results/summary.json)에 있다. 원본과 미리보기는 로컬 `inputs/`, `runs/2026-10-09-local/contact-sheet.jpg`에 보존했다.

## 검증과 실행 문제

- 문자 거리, 누락, 문자 비치환, 영역 일대일 대응, 정답 비참조 대응, top1/top3 분리, 100% 초과 CER를 확인하는 채점 테스트 7개가 통과했다.
- 별도 합성 인쇄체 `ABC123 B-108` 한 장은 원문 완전 일치 및 영역 대응에 성공했다. 인식기와 좌표 변환의 기초 동작 확인용이며 위 성적에 포함하지 않았다. [제어 검사](results/control.json).
- 제한된 실행 환경에서는 38개 호출 모두 `nilError`로 실패했다. 점수는 산출하지 않고 원본 오류를 `runs/2026-10-09-sandbox/`에 보존했다. 로컬 실행 환경에서 같은 표본·코드·설정으로 다시 수행한 38개 호출은 모두 성공했다.
- 보존 결과의 해시와 재채점 일치, 원본 이미지 해시를 `verify.py`로 검증했다.
- 기존 제품 테스트 14개도 재실행해 통과했다. 제품 코드 변경은 없다.

## 재현

저장소 루트에서 실행한다. Python 3.10 이상·Pillow·macOS Vision·Swift 컴파일러가 필요하다. 사용 버전과 소스 해시는 [environment.json](results/environment.json)에 있다. OS가 제공하는 모델 가중치는 별도로 고정하지 못하므로 환경 변경 시 출력 재현을 보장하지 않는다.

```sh
python3 -m unittest discover -s experiments/e1_ocr -p 'test_*.py' -v
python3 experiments/e1_ocr/verify.py
python3 experiments/e1_ocr/prepare.py
python3 experiments/e1_ocr/run.py rerun-001
```

앞의 두 명령은 저장된 결과 검증이다. 뒤의 두 명령은 필요한 공개 자료를 확보하고 새 OCR 실행을 만든다. 이미 있는 실행 폴더나 manifest의 내용은 덮어쓰지 않는다. 새 실행은 자동으로 `results/`의 선별 결과를 교체하지 않는다.

## 결정과 다음 질문

현재 Vision 설정은 비교의 출발점으로 보존하고 제품의 인식기로 확정하지 않는다. **다음에는 방향 보정 또는 대안 인식기 한 가지를 별도 E1-002로 비교한다.** 세로·기울어진 표기 외에도 1/I 등의 오류가 있으므로 방향 보정만으로 해결될 것이라고 단정하지 않는다.

지금 얻은 결과를 작업지시의 부재번호에 강제 치환하면 인식 오류가 가려진다. 제품 연결 시 원문·후보·출처와 확인 필요 상태를 유지해야 한다. 문서 RAG와 맥락 효과 E2~E7은 미실행으로 남긴다.
