# E5-001 — 출력 구조·인용 검사 파일럿

2026-10-09 · E2의 실제 응답 54개에 같은 검사를 적용했다. [프로토콜](PROTOCOL.md), [개별 결과](results/cases.json), [집계](results/summary.json).

## 결론

형식과 출처 ID 검사는 앱 입력을 걸러내는 데 필요하지만 사실 정답을 보증하지 못했다. 검사를 통과한 E2-002의 후보 8개 중 2개는 사전 rubric 기준 불완전 답변이었다. 구조 검사를 통과했다고 용접 판단이나 실행을 승인해서는 안 된다.

| 모델·문서 조건 | 후보 통과 | 그중 사실 정답 | 그중 불완전 답변 | 맞았지만 형식·출처 때문에 확인 대상으로 보낸 사실 답변 |
|---|---:|---:|---:|---:|
| 0.5B 문서 없음 | 0/9 | 0 | 0 | 0 |
| 0.5B 전문 | 0/9 | 0 | 0 | 2 |
| 0.5B 검색 | 0/9 | 0 | 0 | 0 |
| 1.5B 문서 없음 | 0/9 | 0 | 0 | 0 |
| 1.5B 전문 | 3/9 | 2 | 1 | 3 |
| 1.5B 검색 | 5/9 | 4 | 1 | 0 |

단순 JSON 파싱·필드 타입·실제로 제공된 문서 ID·근거 누락을 검사했다. 원문은 수정하지 않았다. UNKNOWN 응답도 대부분 평문이어서 JSON 형식 단계에서 확인 대상으로 분류됐다. 이는 모델이 현장 값을 잘못 지어냈다는 뜻과 다르다.

두 불완전 후보는 E2-002 Q5의 전문·검색 응답이다. 문서 ID는 실제 존재하지만 사전 rubric에서 요구한 내용을 모두 답하지 않았다. 반대로 사실은 맞아도 코드 fence·배열·출처 누락 때문에 처리 가능한 후보로 바로 넘기지 못한 경우가 있었다.

## 검증과 적용 범위

잘못된 출처, 코드 fence 원문 보존, UNKNOWN 처리, 의미 검증 경계, 잘못된 구조·근거 누락을 검증하는 테스트 4개 통과. 실제 응답 54개와 작성한 제어 입력을 구분했다.

```sh
python3 -m unittest discover -s experiments/e5_output_checks -p 'test_*.py' -v
```

`candidate`는 구조와 출처 실재성만 통과했다는 뜻이다. 결과에는 `semantic_verified: false`, `execution_authorized: false`를 유지했다. 이 실험은 재질·두께·WPS 적용성이나 모든 허위 답변을 탐지하는 검사기가 아니다. 최종 확인 흐름과 도메인 근거 대조가 별도로 필요하다.
