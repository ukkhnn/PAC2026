# E4-001 — 실제 OCR에서 가상 작업지시까지

2026-10-09 · 실행 완료. [프로토콜](PROTOCOL.md).

## 결론

실제 전체 이미지 OCR의 42개 관측을 기존 matcher에 연결했다. 정상 가상 맥락에서는 올바른 부재 연결 1개, 다른 블록과 최신 취소 맥락에서는 연결 0개였다. 인식 오류를 계획상의 값으로 교정하지 않은 결과다. 사진에 대응하는 지시는 배포자 라벨에서 만든 가상 자료여서 독립 현장 정확도 실험은 아니다.

| 맥락 | 관측 수 | 연결 | 미연결 | 지원 문자 없음 | 채점 대상의 잘못된 부재 연결 |
|---|---:|---:|---:|---:|---:|
| 정상 가상 블록 | 42 | 1 | 39 | 2 | 0 |
| 존재하지 않는 블록 | 42 | 0 | 40 | 2 | 0 |
| 최신 개정 모두 취소 | 42 | 0 | 40 | 2 | 0 |

42개는 라벨 28개와 다른 분모다. 배경·추가 표기와 difficult 영역의 관측도 포함한다. 사후 IoU 대응으로 채점 가능한 표기에 연결된 올바른 부재는 S08-R06 한 개였다. 실패를 대량 보류한 상태이므로 잘못된 연결 0건을 충분한 시스템 성능이라고 주장하지 않는다.

## 보존한 내용

이미지 해시·인식기·영역·원문 후보·제외 이유·조회 맥락·지시 버전·matcher 원본 결과를 [cases.json](results/cases.json)에 남겼다. 가상 지시의 출처는 [synthetic-orders.json](results/synthetic-orders.json)에 표시했다. 전체 경우에 execution_authorized는 false다.

후보 중 `B 108`처럼 현재 식별자 규약에서 지원하지 않는 값이 있어도 원문을 버리지 않는다. 다른 유효 후보가 하나 연결됐다고 관측이 확정된 것처럼 보이지 않도록 adapter의 review_required를 유지한다. matcher 코드는 수정하지 않았다.

## 검증

작성한 제어 입력으로 잘못된 문자 대안 보존, 복수 후보 보존, O/0 비교정, 전부 미지원 입력의 보존을 확인하는 테스트 4개가 통과했다. 이 제어 입력은 실제 OCR 통계에 포함하지 않았다.

```sh
python3 -m unittest discover -s experiments/e4_linking -p 'test_*.py' -v
```

저장 결과 재현은 상위 실험 검증 스크립트에서 `build()`를 재실행해 확인한다. `run_linking.py`는 선별 결과 디렉토리가 이미 있으면 덮어쓰지 않고 중단한다.

## 범위

이는 실제 OCR 출력과 기존 제품 로직 사이의 실험용 어댑터다. 사진 업로드 UI·운영 데이터 연동·승인 저장을 구현한 것은 아니다. E4의 일반 문서 검색 대비 구조화 조회 우열도 아직 측정하지 않았다.
