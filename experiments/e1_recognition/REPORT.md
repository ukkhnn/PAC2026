# E1-004 — 검출 생략·방향별 문자 인식 결과

2026-10-09 · 실행 완료. E1-003의 crop 검출 누락을 본 뒤 [별도 프로토콜](PROTOCOL.md)로 실행했다.

## 결론

**위치를 알고 검출을 생략한 뒤 네 방향을 읽으면 문자 오류는 줄었지만, 식별자 완전 일치는 여전히 0/28이었다.** 자동 검출 성능 개선이나 제품 정확도로 표현할 수 없는 oracle 진단이다.

| 지표 | 인식 단독 0도 | 인식 단독 네 방향 후보 선택 |
|---|---:|---:|
| 부재번호 완전 일치 | 0/28 | 0/28 |
| 문자 오류 / 정답 문자 | 189/280 | 75/280 |
| CER | 67.50% | 26.79% |
| 상위 3개 내 정답 | 0/28 | 0/28 |
| 전체 후보 내 정답 | 해당 없음 | 0/28 |
| 후보 여러 개 | 해당 없음 | 28/28 |
| 대상당 후보 수 평균(빈 출력 포함) | 해당 없음 | 3.46 |

빈 문자열 15개를 후보 수에서 제외하면 평균은 2.93개이며, 복수 후보 대상은 여전히 28/28이다.

사례별 편집 오류는 17개 감소·10개 동일·1개 증가했다. 오류 감소 114/280 문자, 완전 일치 개선 +0/28을 함께 봐야 한다. 선택은 confidence 내림차순·동점 시 작은 회전각이며 정답을 참조하지 않았다.

## 결정

다음 인식 개선은 문자 혼동과 식별자 전체 정확도를 함께 다뤄야 한다. 이번 정답을 보고 `I→1` 같은 교정을 하거나 부재 목록에 가장 가까운 값으로 덮어쓰지 않는다. 작업지시 연결에서는 원문과 후보를 보존하고 미연결·확인 필요를 허용한다. 새로운 데이터에서의 검증 전에는 자동 확정 근거로 사용하지 않는다.
