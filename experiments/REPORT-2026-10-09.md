# ContextWeld 실험 통합 레포트

2026-10-09 · E1-001 기준선 보존 후 후속 7개 실험 단위를 실행했다.

## 이번에 얻은 결론

**가장 큰 병목은 사진에서 부재번호 전체를 정확히 얻는 단계다.** 방향 처리와 대안 OCR에서 문자 오류가 줄어드는 경우는 있었지만, 자동 전체 이미지 인식의 완전 일치는 최고 1/28에 그쳤다. 작업지시를 이용해 틀린 문자를 강제 치환하면 이 한계가 가려진다.

문서 쪽은 작은 자료집에서 전문 제공이 충분한 기준선이었다. 1.5B 모델의 사실 질문 정답은 전문 5/6, 검색 4/6이었다. 검색기는 필요한 문서를 6/6에서 찾았으므로 실패의 일부는 생성 단계에 있었다. 구조·출처 검사는 필요하지만 사실 정답을 보증하지 못했다.

## 구현·산출물

각 디렉토리에 실행 전 프로토콜, 재현 코드, 실제 출력, 사례별 결과와 레포트를 남겼다. OCR 원본은 기존 manifest를 공유하고, 회전 좌표의 역변환·정답 비참조 후보 병합·대안 인식·문서 제공·가상 지시 연결·구조 검사를 별도 구성했다.

새 실험용 연결 어댑터는 미지원 문자 후보를 사라지게 만들지 않는다. 유효한 다른 후보가 하나 연결돼도 버려진 대안이 있다면 확인 필요 상태로 둔다. 제품 matcher의 원본 결과와 어댑터 상태를 따로 기록했다. 모든 연결과 검사에서 용접 실행 승인은 false다.

제품 `src/contextweld`와 기존 예제는 변경하지 않았다. 사진 업로드 UI·운영 이력 저장·기업 생산시스템 연동을 구현한 것은 아니다. E3의 분할/검색기 비교, E6 이력 효과, E7 전체 제품 평가도 미실행이다.

## 검증

**자동 테스트 35개가 통과했고 저장된 원문에서 모든 결과를 재계산했다.** [검증 기록](VALIDATION.json)과 [보존 해시](checksums.json)에 근거를 남겼다.

| 확인 항목 | 결과 |
|---|---|
| 기존 제품 테스트 | 14개 통과 |
| 문자 채점·회전·검색·어댑터·출력 검사 테스트 | 21개 통과 |
| E1-001 원본·코드·결과 | 기존 해시 유지, 제어 이미지 검사 통과 |
| 후속 OCR 원문 | 후보 재병합·재채점 일치 |
| 생성 응답 | 54개 원문 해시에 연결된 판정과 검색 결과 재현 |
| 연결·구조 검사 | 126개 지시 연결, 54개 출력 검사 재현 |
| 보존 코드·프로토콜·결과 | 76개 파일 해시 확인 |

BM25 점수 재현 중 집합 순회 순서에 따른 약 10⁻¹⁵ 수준 덧셈 차이가 있었다. 검색 문서 ID와 순서는 모두 같았다. 검사기는 점수에만 10⁻¹² 허용오차를 쓰고 ID·순서는 정확히 비교한다. 원문 결과나 검색 코드는 바꾸지 않았다.

```sh
python3 experiments/verify.py
```

위 명령은 모델 재추론·다운로드 없이 결과를 확인한다. 새 추론은 각 실험 레포트의 명령과 새 run_id를 사용한다. 원본·모델·가상환경·실행별 로그는 Git 제외 영역에 보존하고 코드·선별 결과는 검토 가능하게 분리했다.

## 이번 결과의 한계

- 개발 표본·자체 질문이며 독립 테스트나 현장 검증이 아니다. 이미지 라벨과 문서 답변의 도메인 전문가 전수 검수는 하지 않았다.
- 문서 비교는 공개 해설을 바탕으로 작성한 짧은 영어 요약집이다. 한국어·긴 PDF·표·상충하는 규정·실제 WPS를 검증한 결과가 아니다.
- 문서 답변 판정은 사전에 고정한 rubric에 대한 작업 에이전트의 질적 검토다. 부분 답변과 형식 위반을 따로 남겼다.
- 0.5B와 1.5B 실행은 장치·정밀도도 다르다. 모델 크기만의 효과를 분리하지 않았다. 각 모델 안의 문서 제공 비교는 조건을 고정했다.
- 일부 CPU 실험은 동시에 실행되어 시간에 자원 경합이 영향을 주었을 수 있다. [추론] 시간은 재현 참고이며 속도 순위를 주장하지 않는다.
- 공개 자료로 만든 가상 지시와 출처 검사는 기업 승인·작업자의 실제 판단을 대신하지 않는다.

## 다음 작업의 우선순위

1. 다른 원본 묶음의 소량 사진과 라벨·촬영 방향을 검수한다. 기존 오류를 보고 I/1 등을 정답에 맞춰 교정하지 않는다.
2. 필요한 경우 수기 인식 또는 VLM 대안 한 가지를 같은 기준으로 비교한다. 최종 테스트 분할은 개발에 쓰지 않는다.
3. 실제 긴 문서·표가 확보되면 검색이 필요한 질문부터 E3를 진행한다. 현재 짧은 자료집에서는 전문 제공 기준선을 유지한다.
4. 제품 연결은 원본·후보·근거·확인 필요를 보여주는 좁은 흐름부터 시작한다. 자동 확정이나 임의의 용접 수치 추천을 추가하지 않는다.

이번에는 커밋·push·배포를 하지 않았고, 기존 사용자 자료와 제품 코드를 보존했다.
