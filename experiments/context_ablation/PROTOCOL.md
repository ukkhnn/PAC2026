# CTX-001: 고정 이미지의 주변 장면·작업 문맥 비교

작성일: 2026-10-10. 새 Runpod 실행 전 입력과 비교 조건을 고정한다. 과거 서버 이전 OCR·문서 실험의 성적은 이번 기준선 및 발표 근거에 포함하지 않는다. 원본 사진과 공개 라벨은 재사용하며 과거 파일은 삭제·수정하지 않는다.

## 질문과 범위

**문자 판독만으로 모호한 표기를 주변 이미지와 합성 작업 문서가 올바른 부재 식별로 연결하는가? 문서가 틀리면 오히려 잘못된 확정을 늘리는가?**

실제 현장 작업지시가 없는 공개 철골 사진에 통제된 합성 후보·배치 문서를 제공하는 소규모 개발 진단이다. 이미지의 대상 영역은 공개 정답 라벨에서 주어지므로 자동 검출 성능이나 전체 서비스 성능을 측정하지 않는다. 이 실험에서 부재 식별이 맞아도 실제 이음·재질·두께·WPS 적용성이 입증되지는 않는다. 카메라 위치 변경, Isaac 실행·수정, 이미지 훼손·보정, 추가 촬영은 하지 않는다.

## 입력 모집단

| 항목 | 고정 내용 |
|---|---|
| 사진 | 기존 확보한 Steel OCR 공개 사진 10장, 원본 SHA-256 일치 확인 |
| 원본 선택 기준 | 당시 train 경로 SHA-256 순서의 앞 10장. 이번 결과를 보고 골라내지 않음 |
| 평가 대상 | `difficult=false` 28표기, 9사진. S10의 difficult 표기 1개는 사전 제외 |
| 대상 ROI | 라벨 polygon의 축정렬 bbox에 가로·세로 각각 8%, 최소 4px padding. 이미지 경계로 제한 |
| 이미지 처리 | 원본 RGB crop → PNG. 회전·원근보정·확대·합성 없음 |
| 정답 | 공개 transcription. 새 독립 전문가 검수는 없음. 문자 exact와 부재 연결을 별도 채점 |
| 자료 출처 | `iput-tk230215/steel-ocr-dataset-960`, revision `37725284f40deeaccbdeb3734be7b0e90e974305` |
| 공개 이용 표기 | 데이터 카드 MIT 표기, 별도 LICENSE 파일은 당시 목록에서 확인하지 못함. 저장소에는 원본 사진을 추가하지 않음 |

S06 11표기와 S08 7표기가 18/28을 차지한다. 표기 28개를 독립 사진 28장처럼 설명하지 않는다. 전체 문항 수와 사진별 결과, 사진별 비율 평균을 함께 보고한다. 정답·이미지의 기사용 이력이 있으므로 독립 평가셋이나 일반화 성능으로 주장하지 않는다.

## 비교 조건

| 조건 | 모델 입력 | 비교 목적 |
|---|---|---|
| A | 동일 target crop → 현재 Runpod Paddle OCR | 새 OCR 기준선. 과거 whole-image OCR 결과는 사용하지 않음 |
| B | target crop + 고정된 A 원문 | VLM의 시각 재판독 |
| C | B + 원본 전체 이미지 + 대상 위치 | 주변 시각 정보의 추가 효과 |
| D | C + 부재 후보 ID 6개 | 후보 목록으로 해석 범위를 좁히는 효과 |
| E | D + 후보별 합성 배치·작업 정보 | 후보만 제공한 것 이상의 문서 효과 |
| F_context_only | A 원문 + E의 후보·작업 정보·주어진 대상 ROI 위치·전체 이미지 크기, 이미지 bytes 없음 | 이미지 없이 OCR·위치·문서로 얻는 효과. 순수한 ‘문서만’ 조건은 아님 |
| RULE_D | A 원문과 D 후보의 문자열 거리 | 간단한 후보 대조만으로 설명되는 개선 |
| E_absent | E와 같은 이미지·A 원문, 정답이 빠진 목록·문서 | 목록 밖 판독/보류 여부, 비슷한 후보로의 강제 선택 |
| E_wrong | E와 같은 이미지·A 원문·후보, 잘못된 배치 정보 | 문서 유도 오답, 충돌 표시와 보류 여부 |

A 및 정상 B~E·F_context_only·RULE_D는 28개 전체에 적용한다. E_absent/E_wrong은 실행 결과와 무관하게 `S01-R00`, `S03-R00`, `S06-R00`, `S08-R00` 4개를 고정한다. 각 부정 조건의 분모는 4개이며 정상 조건의 28개와 합치지 않는다.

B~E와 보조 VLM 조건은 같은 Qwen3-VL-8B·온도 0·출력 한도 512·기본 지시문·출력 계약을 사용한다. 실제 모델 revision, 이미지 입력 크기·토큰 수, 생성 토큰 수, 프롬프트, 원문 응답, 오류, 시간을 남긴다. C 이후에는 같은 crop을 유지하고 전체 이미지를 추가한다. C/D/E/F 및 E 부정 조건에는 동일하게 공개 라벨 ROI를 0~1000으로 정규화한 `target_region_1000`과 `scene_image_size`를 제공한다. F는 E에서 이미지 bytes만 제외한다. 해상도·토큰 예산 때문에 실제 crop 입력 크기가 달라지면 기록하며 단순한 시각 문맥 효과로만 해석하지 않는다.

A 결과는 한 번 생성해 B 이후 동일한 원문을 제공한다. B 결과가 C로, C 결과가 D로 전달되는 연쇄 추론은 하지 않는다. 각 호출은 새 대화로 실행한다. 잘못된 형식·출력 잘림도 실패 결과로 보존하며 결과를 본 뒤 유리한 응답으로 교체하지 않는다. 실행 문제를 고치면 변경 전 결과를 보존하고 새 실행 ID와 변경 이유를 남긴다.

RULE_D는 A의 대상 문자 후보와 ID 목록 사이 최소 Levenshtein 거리 후보를 찾는다. 양끝 공백 제거·대문자화만 허용하며 `1/I`, `0/O`를 자동 치환하지 않는다. 유일한 최소 후보이고 거리가 2 이하인 경우만 선택하고 나머지는 보류한다. VLM과 규칙의 차이를 보고해 단순 문자 근접 효과를 의미 추론 성과로 설명하지 않는다.

## 합성 작업 문서의 작성과 한계

후보·문서는 새 모델 출력을 읽기 전에 공개 라벨로 결정한다. 공개 입력의 `source_kind=synthetic_demo`, `placement_basis=annotation_derived_coarse_image_layout`, `real_work_order=false`를 유지한다. 실제 사진의 현장 업무·재질·두께·용접조건을 추정해 넣지 않는다.

각 정상 목록은 6개이며 정답, 미리 정한 문자 혼동 후보, 같은 사진의 인접 표기 후보, 부족한 경우 숫자가 가까운 후보로 구성한다. 모든 후보 순서는 문항 ID·후보 문자열의 고정 SHA-256 순서다. D와 E의 ID 목록·순서는 같다. 정답 여부·정답 인덱스·최종 채점 결과는 모델 입력에 없다.

E 문서는 좌/중/우, 상/중/하의 넓은 위치와 가장 가까운 다른 표기의 대략적인 방향만 제공한다. 정확한 라벨 좌표나 정답 표식은 문서에 넣지 않는다. `nearby_markings`의 문자열은 다른 라벨에서 가져온 **합성 문서의 참조 정보**이며 그 표기를 모델이 실제로 읽었다는 뜻이 아니다. crop을 전체 이미지에서 지칭하는 대상 ROI 좌표는 관측 대상 지정 정보이며 문서 내 후보별 좌표와 구분한다.

정상 문서의 정답 후보와 첫 문자 `1/I` 혼동 후보는 **같은 배치·인접 정보**를 가진다. 문서 위치만 대조해 항상 하나로 확정할 수 없게 하는 의도적 모호함이다. 단일 표기 사진은 후보 모두 `unspecified` 위치와 동일한 중립 작업 정보를 가진다. 이 사진에서는 E가 D보다 좋아야 한다는 기대를 두지 않는다.

정답 포함을 알고 만든 후보 목록과 라벨에서 파생한 배치 문서는 유리한 가정을 제공한다. 따라서 D/E의 향상은 실제 현장 문서 검색 성공률·자연스러운 작업지시 분포·독립 공간 추론을 증명하지 않는다. F_context_only, RULE_D, 잘못된 문서 조건을 함께 보고한다. 원문 응답의 설명이 그럴듯하다는 이유만으로 실제 근거 사용이 검증됐다고 표시하지 않는다.

E_absent는 목록 길이·순서를 유지하며 정답 ID를 다른 후보로 바꾸고 문서의 인접 참조에서도 정답 문자열을 제거한다. E_wrong은 동일 ID 목록에서 정답 후보의 배치를 다른 곳으로 바꾸고 비슷한 후보의 배치를 원래 위치에 둔다. 이 잘못된 배치는 결함 주입이며 실제 사진 사실이 아니다.

## 데이터 계약과 보존

| 파일 | 역할 |
|---|---|
| `inputs.json` | 원본 경로·해시·크기, 평가 대상 ID·polygon·bbox, 합성 문서 참조. transcription 없음 |
| `fixtures.json` | 조건별 후보 목록과 합성 문서. 정답 표시 없음 |
| `ground_truth.json` | 정답 문자열·사진 그룹·제외 사유·부정 조건 기대 동작. 채점 단계 전용 |
| `prepare.py` | 공개 원본·해시 검증, 결정적 정의 작성, 별도 출력 경로에 crop 준비 |

실제 모델 호출은 inputs·fixtures와 이미지·A 출력으로만 구성한다. ground_truth나 과거 실험 출력은 프롬프트에 보내지 않는다. 생성된 이미지 경로도 `Sxx`/`Sxx-Ryy` 형태로 익명화해 원래 파일명의 표기가 모델 입력 텍스트에 섞이지 않게 한다.

정의 파일과 코드·프롬프트의 SHA-256을 첫 추론 전에 실행 묶음에 기록한다. 정의 파일 덮어쓰기와 완료 실행 재사용은 거절한다. 원본 사진·라벨·이전 모델 결과·Isaac 장면과 프로세스는 보존한다. 원문 모델 응답, 입력, 오류와 생성된 crop은 Git 제외 output에 저장한다.

정의 확인과 crop 준비 예시:

```sh
python3 experiments/context_ablation/prepare.py --verify-only
python3 experiments/context_ablation/prepare.py --output-dir output/context-ablation/prepared-01
```

`--freeze`는 새 정의를 처음 작성할 때만 사용하며 기존 정의가 있으면 실패한다. 일반 재실행에서는 `--verify-only`로 동결 정의를 검증한다. 공개 원본·모델 새 다운로드와 패키지 설치는 이 준비 스크립트의 기능이 아니다.

## 채점과 해석

문자 완전 일치는 양끝 공백 제거·대문자화한 지표와 대소문자까지 보존한 지표를 모두 보고한다. 부재 ID 연결도 양끝 공백 제거·대문자화 후 비교한다. `1/I`, `0/O` 혼동은 모든 지표에서 오답이다. 원문을 고치지 않고 파생 채점값을 별도로 저장한다.

정상 조건마다 문자 exact, 올바른 연결, 틀린 확정, 보류, 형식 오류·실행 실패, 처리 시간을 절대 문항 수와 함께 보고한다. 같은 문항의 A→B, B→C, C→D, D→E, F_context_only→E에서 오답→정답과 정답→오답을 모두 집계한다. 모델 선언의 자신감은 정답 여부로 취급하지 않는다.

부정 조건은 정답이 없는 목록에 억지로 선택했는지, 틀린 배치 때문에 원래 맞던 해석을 바꿨는지, 목록 밖 판독·문서 충돌·보류를 표시했는지 따로 본다. 판독 문자열은 맞지만 목록에서 다른 부재를 선택한 경우를 성공으로 합치지 않는다. 보류를 많이 하는 것만으로 안전성이나 정확성을 주장하지 않는다.

발표에는 개선 사례와 반례를 같이 제시한다. 예를 들어 ‘28개 중 몇 개를 새로 해결했고 몇 개를 망쳤다’, ‘그 효과가 이미지 추가에서 생겼는지 후보 목록만으로 생겼는지’를 설명한다. 사전 합격선을 정하지 않으며 유리한 결과가 나오도록 대상·문서·정답을 사후 수정하지 않는다.
